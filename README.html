BuzzAgent

🌐 Project site: https://b4zz.com/agent

Open-source visual workbench for AI coding agents. The agent core is OpenCode (MIT); BuzzAgent is the GUI client around it — not another agent runtime.

See everything the agent does. Control models, tools, browser, MCP, and reasoning — locally, with zero telemetry.

Why this exists

Visual agent tools are locked to an IDE and ship telemetry (Cline, Kilo Code, Roo Code); terminal agents are powerful but blind (OpenCode, Claude Code, Codex CLI, Oh My Pi). The gap is a product that keeps terminal-agent power and gives visual control, without telemetry or vendor lock-in.

BuzzAgent does not reimplement the agent. OpenCode is already a headless HTTP server (opencode serve) with an OpenAPI spec, an SSE event stream and a typed JS SDK. Their TUI is one client; their IDE plugins are another. BuzzAgent is the third: a standalone desktop GUI.

What it does

  • Streaming chat with tool-call cards, per-role reasoning and model routing. Slash commands: /init (write AGENTS.md), /compact, /export, /copy, /undo, /redo, /help; @file references; !command shell passthrough. Project commands (GET /command) always win over built-ins.
  • Visual diffs with word-level highlights and single-file revert; parallel agents in per-branch git worktrees.
  • Providers: 75+ via the core; API key or OAuth; the model picker has an inline “connect” section for unconnected catalogue providers; two-way merge-only sync of keys and custom providers with your personal opencode CLI state.
  • Session insight: token/cost totals and a context-window meter in the status bar, per-message breakdown.
  • Desktop shell: custom (VS Code style) or system window frame, tray icon, 15 interface languages.

Architecture

┌─────────────────────────────────────────────────────────┐
│  BuzzAgent (Tauri + React)                              │
│                                                         │
│  Visual layer  ──HTTP + SSE──►  opencode serve          │
│  chat · diffs · files ·         (sidecar binary,        │
│  providers · permissions ·       pinned version)        │
│  worktrees                                              │
│                                                         │
│  Rust layer                                             │
│  · supervise the core process                           │
│  · embedded browser (CDP)  ──registered as a core tool──│
│  · git worktree orchestration                           │
└─────────────────────────────────────────────────────────┘

The frontend talks to the core directly over HTTP/SSE (SDK generated from a pinned spec). Rust never proxies agent traffic: it spawns and supervises opencode serve and exposes native tools the core cannot do itself.

Zero telemetry — verified

  • No third-party analytics SDKs in the core binary.
  • Outbound channels forced off (share: "disabled", autoupdate: false).
  • All XDG roots isolated inside the app data dir; loopback forced into NO_PROXY.
  • HTTP Basic with a random 64-character password, bound to 127.0.0.1 only.

Reproduction steps: docs/telemetry-audit.md.

Quick start

npm install
npm run setup:core   # downloads the pinned OpenCode core binary
npm run dev          # runs the desktop app
npm run dist         # builds installers (built with the core inside)

CI builds Windows .msi/.exe, macOS .dmg and Linux .deb/.rpm/.AppImage on a version tag and attaches them to the GitHub Release.

Verification & tests

npm run typecheck    # TypeScript strict check
npm run lint         # ESLint 9
npm test             # Vitest unit suite
cd src-tauri && cargo test   # Rust supervisor, git, browser tests
npm run test:integration     # end-to-end against a live core + mock provider
