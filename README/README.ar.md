# BuzzAgent — العربية (README.ar.md)

🌐 موقع المشروع: **https://b4zz.com/agent**

⬇️ **تنزيل:** [https://b4zz.com/agent/#download](https://b4zz.com/agent/#download)

مساحة عمل بصرية مفتوحة المصدر لوكلاء البرمجة بالذكاء الاصطناعي. نواة الوكيل
هي [OpenCode](https://github.com/anomalyco/opencode) (رخصة MIT)؛ وBuzzAgent
هو عميل الواجهة الرسومية حولها — وليس وقت تشغيل وكلاء آخر.

> **شاهد كل ما يفعله الوكيل. تحكّم في النماذج والأدوات والمتصفح وMCP
> والاستدلال — محليًا، وبدون أي قياس عن بُعد.**

## لماذا وُجد هذا

السوق منقسم إلى نصفين:

**مرئي لكنه ضعيف.** Cline وKilo Code وRoo Code — واجهة صالحة للاستخدام، لكنها
محبوسة داخل VS Code، مع تتبّع المستخدم وحلقة وكيل أضعف.

**قوي لكنه أعمى.** OpenCode وClaude Code وCodex CLI وOh My Pi — وكيل قوي، لكن
هو طرفية فقط. لا مقارنات مرئية للفروقات، ولا متصفح داخل التطبيق، ولا تنسيق
لمساحات العمل.

الفجوة هي منتج يحافظ على قوة وكلاء الطرفية **ويمنح** تحكمًا بصريًا، دون قياس
عن بُعد ودون حبس مزوّد الخدمة.

BuzzAgent هو ذلك المنتج. إنه **لا يعيد بناء الوكيل**. فـ OpenCode نفسه خادم
HTTP بلا واجهة (`opencode serve`) مع مواصفات OpenAPI، وتدفق أحداث SSE، وحزمة
JS موثّقة الأنواع. واجهتهم الطرفية TUI هي عميل لذلك الخادم؛ وإضافات IDE
لديهم عميل آخر. BuzzAgent هو العميل الثالث: واجهة رسومية سطح مكتب مستقلة.

سطر أوامر Kilo Code هو **تفرّع (fork)** من OpenCode ثم لُفّ كإضافة VS Code
(من سلالة Cline) مع حسابات وتتبّع. نحن لا ننسخ ذلك. التفرّع يورث تكلفة
صيانتهم ويقطعنا عن المنبع. أما العميل فيُبقي النواة محدّثة كلما أصدرت
OpenCode نسخًا جديدة، وهو ما تفعله باستمرار.

### OpenCode الآن تُصدر واجهتها الرسومية الخاصة

منذ الإصدار 1.18 ينشر مستودع OpenCode بناءات `opencode-desktop-*`
(Electron + SolidJS، بحجم ~120–150 MB) ووضع المتصفح (`opencode web`). لذا
فإن «عميل مرئي لـ OpenCode» **لم يعد ميزة مميزة بحد ذاته** — فمؤلفو النواة
لديهم واحد.

ما ما زال لنا:

- **صفر تتبّع كحقيقة قابلة للتحقق.** تطبيق سطح المكتب لديهم يدمج
  `@sentry/solid` ويهيّئه عند ضبط `VITE_SENTRY_DSN` وقت البناء
  (`packages/desktop/src/renderer/index.tsx`)، إضافة إلى `sentryVitePlugin`
  في البناء. عمليتنا بلا أي أداة تقارير أعطال وبلا أي اعتمادية تحليلات.
- **متصفح داخل حلقة الوكيل** — يكتب الكود، ويفتح النتيجة، وتعود لقطة الشاشة
  كنتيجة أداة، فيصلح. ليس headless فقط: يتصل أيضًا بمتصفح Chrome قيد
  التشغيل عبر CDP، ليعمل الوكيل على ملف شخصي سجّل المستخدم دخوله مسبقًا
  (خاضع للأذونات مثل `shell_exec`).
- **تنسيق أشجار العمل (worktrees)** — عدة وكلاء بالتوازي على فروع معزولة، مع
  مراقبة بصرية.
- **بلا حساب، وبلا بوابة مضمّنة.** لا مسار افتراضي عبر Zen/Go.

النتيجة: ستُقارن واجهتنا الرسومية مباشرة بواجهتهم. هذا يرفع سقف الجودة، وهو
سبب أن يكون الإنجاز الأول (Milestone 1) شريحة ضيقة وموثوقة لا جولة ميزات
واسعة.

سابق مفيد من تطبيق سطح المكتب لديهم: `packages/desktop/src/main/sidecar.ts`
يشغّل الخادم مع `OPENCODE_SERVER_PASSWORD`، ومنفذ عشوائي، وCORS محصور على
أصل واجهتهم فقط، وإجبار عناوين loopback في `NO_PROXY`، وتحميل شهادات CA
النظام. نعتمد التحصين نفسه.

## المعمارية

```
┌─────────────────────────────────────────────────────────┐
│  BuzzAgent (Tauri + React)                              │
│                                                         │
│  الطبقة البصرية  ──HTTP + SSE──►  opencode serve         │
│  محادثة · فروقات · ملفات ·     (ثنائي sidecar،           │
│  مزوّدون · أذونات ·             إصدار مثبّت)              │
│  أشجار العمل                                             │
│                                                         │
│  طبقة Rust                                               │
│  · الإشراف على عملية النواة                               │
│  · متصفح مدمج (CDP) ──مسجّل كأداة نواة──                  │
│  · تنسيق git worktrees                                   │
└─────────────────────────────────────────────────────────┘
```

- **النواة = OpenCode.** حلقة الأدوات، استدعاء الدوال الأصلي، البث، الجلسات
  والاستئناف، الضغط، الأذونات، LSP، MCP، grep/glob/symbols، AGENTS.md،
  المهارات، أوامر الشرطة المائلة، أكثر من 75 مزوّدًا، OAuth. لا نعيد كتابة
  شيئًا من هذا.
- **الواجهة = BuzzAgent.** محادثة ببطاقات استدعاء الأدوات، فروقات بصرية،
  شجرة ملفات، صندوق وارد للأذونات، تحكم بالطراز/النموذج حسب الدور، مراقب
  أشجار العمل.
- **إضافات أصلية لا تتوفر في النواة.** متصفح مدمج في حلقة الوكيل؛ وكلاء
  متوازون في أشجار git عمل معزولة.

تتحدث الواجهة الأمامية مع النواة **مباشرة** عبر HTTP وSSE، مستخدمة
`@opencode-ai/sdk` المولّدة من مواصفات OpenAPI **مثبّتة الإصدار**
(`GET /doc`). لا تمرّر Rust أي حركة مرور للوكيل. تقوم Rust فقط بـ:

1. تشغيل `opencode serve` والإشراف عليه (منفذ عشوائي، كلمة مرور، فحص صحة).
2. كشف الأدوات الأصلية التي لا تستطيع النواة فعلها بنفسها (المتصفح، أشجار
   العمل).

وهو نفس الفصل الذي تستخدمه OpenCode داخليًا: الواجهة الطرفية عميل، والخادم
هو بيئة التشغيل.

## لماذا Tauri (وما كلفته)

المسار الساخن — تدفّق الرموز، بطاقات الأدوات، الفروقات — يذهب مباشرة من
webview إلى النواة المحلية عبر HTTP/SSE. **لا يمر** عبر IPC الخاص بـ Tauri،
لذا فإنتاجية اتصالات الغلاف ليست في المسار الحرج. هذا يجعل غلاف سطح المكتب
قرار تغليف وقدرات أصلية، لا قرار أداء.

Tauri، لأن:

- نحتاج أصلًا طبقة أصلية للإشراف على العمليات والتحكم بالمتصفح عبر CDP
  وأشجار git العمل؛ ذلك الكود موجود واختباراته ناجحة.
- الانتقال إلى Electron يضعنا على المكدس نفسه لتطبيق OpenCode سطح المكتب
  (Electron + SolidJS + sidecar)، حيث يسبقنا مؤلفو النواة ولن نميّز شيئًا.
- قالب Electron لديهم يأتي مع تكامل Sentry. وعدنا «بلا تتبّع» أسهل في بقائه
  صحيحًا على مكدس نتحكم به.
- حجم الحزمة حجة ضعيفة هنا: ثنائي النواة وحده ~57 MB، فالفرق بين غلاف بحجم
  5 MB و120 MB ليس حاسمًا.

الكلفة الحقيقية، بصراحة:

- **ثلاثة webviews مختلفة.** WebView2 (Chromium، يحدّث نفسه) على Windows،
  وWKWebView على macOS، و`webkit2gtk` على Linux. حسب جدول Tauri نفسه،
  `webkit2gtk` 2.36 ≈ Safari 16، والتوزيعات الأقدم أبعد من ذلك. لينكس هو
  الهدف الأضعف وهو حيث سنرى أخطاء العرض أولًا. التخفيف: CSS محافظ، لا واجهات
  ويب حدّية، واختبار على `webkit2gtk` حقيقي.
- **عدة webviews في نافذة واحدة خلف راية `unstable` في Tauri.** يهمّ لوحة
  المتصفح: نفضّل CDP + لقطات شاشة/بث داخل الواجهة بدل تضمين webview ثانٍ
  حي، أو قبول نافذة منفصلة.
- أزمنة بناء Rust ونظام إضافات أصغر من بيئة Electron.

### البدائل التي جرى النظر فيها

| الخيار | الحكم |
|---|---|
| **Electron** | أكثر تجربة مستخدم قابلية للتنبؤ: Chromium واحد في كل مكان، أوسع منظومة، أسهل أدوات تطوير. رُفض كخيار افتراضي لأنه بالضبط مكدس تطبيق OpenCode سطح المكتب، ولسنا نزال سنحتاج كودًا أصليًا عبر إضافات node. البديل الصادق إذا أصبحت أخطاء `webkit2gtk` لا تُدَار. |
| **Go + Wails** | نموذج webview النظام نفسه كـ Tauri، فيرث مشكلة `webkit2gtk` ذاتها مع التخلي عن كود Rust الموجود. Go لا تشتري شيئًا هنا: النواة ليست Go، وعملنا الأصلي (CDP، أشجار العمل، الإشراف) ليس أسهل في Go. |
| **واجهة Rust خالصة** (egui، Iced، GPUI، Dioxus native، Slint) | تزيل فئة أخطاء webview كلها وتمنح أداء أصليًا حقيقيًا. لكننا سنبنى يدويًا المحادثة وmarkdown وتلوين الصياغة وعرض الفروقات وشجرة الملفات — وهي بالضبط السطح الذي يُحكم فيه على واجهة وكيل برمجة. منعطف متعدد السنوات، ولوحة المتصفح تصبح صعبة جدًا. غير عملي للإصدار الأول. |
| **واجهة ويب فقط** (نقدّم واجهتنا في متصفح) | الأرخص، وهدف ثانوي مفيد فعلًا — لكن OpenCode تُصدر `opencode web` أصلًا، وتبويب متصفح لا يملك قوائم أصلية ولا أشجار عمل ولا متصفحًا مدمجًا. جيد كوضع إضافي لاحقًا، لا كمنتج. |
| **Flutter / .NET / Qt** | عناصر بجودة أصلية، لكن دون إعادة استخدام React، ومنظومة «عرض markdown + فروقات + كود» أضعف من الويب. إعادة كتابة كبيرة بلا مكسب استراتيجي. |
| **إضافة VS Code** | مألوفة ورخيصة، لكنها صندوق Cline/Kilo الذي نتموضع ضده صراحة، وتقتل قصة التطبيق المستقل/بلا تتبّع. |

القرار: **Tauri + React الآن**، مع Electron كخطة بديلة موثّقة إذا ثبت أن
عيوب webview على لينكس لا تُدَار. إبقاء الواجهة عميل HTTP/SSE بسيطًا للنواة
هو ما يجعل تلك الخطة بديلة رخيصة — الغلاف قابل للاستبدال لأن منطق الوكيل لا
يعيش فيه.

### لماذا لا Oh My Pi كنواة

[oh-my-pi](https://github.com/can1357/oh-my-pi) (MIT، ~30 ألف نجمة) وكيل قوي
— وأعمق من OpenCode في مواضع: LSP داخل الحلقة، DAP، تعديلات hashline، طبقة
Rust أصلية كبيرة، مخططات `pr://`/`issue://`/`agent://`، سلاسل بدائل للنماذج.
وهو رغم ذلك النواة الخطأ *لهذا المنتج*:

- **لا خادم HTTP.** أسطحه أربعة: الواجهة الطرفية، وأمر واحد (prompt)، وحزمة
  Node داخل العملية، و`--mode rpc` / `acp` عبر **stdio**. المتصفح لا يتحدث
  stdio، لذا على Rust أن يوسّط كل رسالة — الطبقة التي أزلناها عمدًا —
  ويتطلب RPC لديهم تقطيع إطارات يدوي بحجم 1 MiB وتفاوض بروتوكول. بلا مواصفة
  OpenAPI لا يوجد عميل مولّد.
- **تتبّع لا يمكن إيقافه.** معرّف تثبيت دائم (`~/.omp/install-id`، موثّق في
  `docs/install-id.md` لديهم) ينجو من محو حالة الوكيل ويغذّي، من بين غيره،
  تقرير استخدام لدليل مصادقة يرسل أيضًا اسم المضيف، ودفاعات auto-QA. إزالته
  تعني تفرّع وقت التشغيل لديهم، وهو ما يهدم ميزة الاعتماد على نواة غيرنا.
- **المكانة محجوزة:** `gooey-pi` و`pi-desktop` و`ohmypi-craft` و`ompweb`
  واجهات رسومية لـ OMP أصلًا.

إذا أضفنا يومًا نواة ثانية فستمر عبر **ACP** — بروتوكول مشترك — خلف واجهة
محوّلة، وفقط بعد أن تنضج شريحة OpenCode.

## جودة الواجهة هي المنتج

كل ما سبق سباكة. سبب اختيار BuzzAgent هو الواجهة، لذا تُحاسَب على معيار لا
على «تعمل»: لا شيء يعلّق على الشبكة، و60 إطارًا/ثانية أثناء البث، ولا انزياح
تخطيط، وأولوية للكيبورد، وفروقات حقيقية جنبًا إلى جنب مع تلوين الصياغة،
وجلسات طويلة افتراضية العرض، وحالات فارغة/خطأ/انقطاع مصمّمة، وسمات داكنة
**وفاتحة**، وإتاحة حقيقية (تركيز، تباين، دعم قارئ الشاشة لتدفق الرسائل).

المعيار الكامل، ومكدس الواجهة المختار (React 19، Tailwind 4، Radix، Shiki،
CodeMirror 6، TanStack Virtual، cmdk)، وقواعد إضافة الاعتماديات في
PLAN.md.

## كيف يصل إعداد إلى النواة

لا تحتفظ الواجهة بنسخة ثانية من حالة النواة أبدًا. مثال — المستخدم يلصق مفتاح
API:

1. تستدعي لوحة النماذج `GET /provider/auth`. يُبنى النموذج من المخطط الذي
   تعيده النواة (مفتاح API، OAuth، تدفق الجهاز، …).
2. عند الحفظ تستدعي الواجهة `PUT /auth/:id`. تكتب النواة
   `~/.local/share/opencode/auth.json`. المفتاح لا يبقى في مخزننا ولا في
   `localStorage`.
3. عنوان URL الأساسي والقائمة البيضاء للنماذج و`share: "disabled"` تمر عبر
   `PATCH /config`.
4. منتقي النماذج هو `GET /config/providers` / `GET /provider`.
5. نموذج الدور الواحد حقل في `POST /session/:id/message` (`model`،
   `agent`). «موجّه حسب الدور» هو واجهتنا تختار هذه الحقول — وليس عميل HTTP
   ثانيًا أمام 75 مزوّدًا.

مزوّدو OAuth (Claude Pro، Copilot، GitLab Duo، DigitalOcean) يستخدمون
`POST /provider/{id}/oauth/authorize` ← متصفح النظام ←
`POST /provider/{id}/oauth/callback`. لا كود خاصًا بمزوّد في جهتنا.

لو تباعد مخزنان مرة أخرى فلن يبدأ الوكيل. النواة هي المالك الوحيد
للإعدادات والجلسات والفروقات والأذونات.

## ما نبنيه وما لا نبنيه

**لا نكتب:** المزوّدين، OAuth، حلقة الأدوات، البث، الجلسات، الضغط، محرك
الأذونات، LSP، MCP، grep/glob/symbols، AGENTS.md، أوامر الشرطة، المهارات،
المهام.

**نكتب:** الطبقة البصرية كاملة؛ المتصفح المدمج كأداة نواة؛ تنسيق أشجار
العمل؛ صندوق الأذونات؛ موجّه النماذج/الجهد البصري؛ الإشراف على العمليات؛
التغليف.

**لا نتفرع من OpenCode** إلا إذا أثبتت شريحة عمودية وجوب تغيير دلالات النواة
(تعليمات النظام، سلوك الأدوات، تجهيز الفروقات). يُتخذ ذلك القرار بالأدلة بعد
الإنجاز الأول، لا مسبقًا.

## التموضع

```
BuzzAgent = نواة OpenCode
          + تحكم بصري بمستوى Cline
          + تنسيق أشجار عمل بمستوى Orca
          + متصفح مدمج في حلقة الوكيل
          + صفر تتبّع
```

| | BuzzAgent | Cline / Kilo | Cursor | Claude Code | OpenCode |
|---|---|---|---|---|---|
| مفتوح المصدر | نعم | نعم | لا | لا | نعم |
| صفر تتبّع | نعم (مدقّق — انظر أدناه) | لا | لا | لا | تقريبًا (share/Zen اختياري) |
| واجهة بصرية | سطح مكتب مستقل | VS Code | نعم | لا | TUI / ويب |
| متصفح مدمج في الحلقة | نعم | لا | لا | لا | لا |
| تنسيق أشجار العمل | نعم | لا | لا | لا | جلسات فقط |
| وكلاء فرعيون، LSP، MCP، أذونات | عبر النواة | جزئي | جزئي | نعم | نعم |
| تجاوز الوكيل لاحقًا | واجهة محوّلة، OpenCode أولًا | لا | لا | لا | لا ينطبق |

أثبت Kilo Code أن نواة OpenCode تحمل منتجًا، ورخصة MIT تسمح به. ثم احتلوا
مساحة IDE + التتبّع + الفواتير. المساحة التي تركوها فارغة هي هذه بالضبط: سطح
مكتب مستقل، بلا حساب، بلا تتبّع، متصفح + أشجار عمل.

## صفر تتبّع — مُتحقَّق منه

اكتمل التدقيق (الإنجاز 0) وتحقق منه تجريبيًا. خطوات إعادة الإنتاج الكاملة في
[docs/telemetry-audit.md](./docs/telemetry-audit.md).

- **صفر تتبّع من أطراف ثالثة.** لا Sentry ولا PostHog ولا Segment ولا
  Mixpanel ولا Datadog ولا أي SDK تحليلات في ثنائي النواة.
- **استدعاءات الشبكة الصادرة مغلقة قسرًا.** مشاركة المحادثات
  (`"share": "disabled"`)، والتحديث الذاتي (`"autoupdate": false`)، ونماذج
  Zen الصغيرة، كلها مُطفأة عبر إعدادات مفروضة على القرص.
- **بيئة معزولة.** كل الحالة وذاكرة التخزين المؤقت وقاعدة البيانات والسجلات
  داخل مجلد بيانات التطبيق (`XDG_CONFIG_HOME`، `XDG_STATE_HOME`،
  `XDG_DATA_HOME`، `XDG_CACHE_HOME`).
- **الأمان.** مصادقة HTTP Basic بكلمة مرور عشوائية من 64 حرفًا، والربط على
  `127.0.0.1` فقط.

## الحالة الحالية

أُعيد بناء BuzzAgent وهو يعمل بكامل وظائفه:
- **مشرف النواة (Rust)**: إدارة تلقائية للعملية، منفذ عشوائي، توليد كلمة
  مرور، فحوص صحة، عزل للبيئة، تجاوز `NO_PROXY` للـ loopback، وإغلاق نظيف عند
  الخروج.
- **عميل HTTP + SSE مباشر**: اتصال مباشر بواجهة نواة OpenCode، تحليل تدفق
  الأحداث بصمود عند حدود الإطارات، إدارة جلسات، رسائل متعددة الأدوار، وبوابة
  أذونات.
- **واجهة مساحة العمل البصرية**: محادثة بث حي مع markdown لا يومض، وكتل كود
  ملوّنة صياغيًا (Shiki)، وبطاقات أدوات قابلة للفحص بالحالات/المدد/الأخطاء،
  وحوارات الأذونات.
- **لوحة الفروقات البصرية**: عيّن تغييرات git في الوقت الحقيقي بعلامات على
  مستوى الكلمة (`+`/`−`) واسترجاع ملف بنقرة واحدة.
- **لوحة المتصفح المدمج**: أتمتة Chrome بلا واجهة واتصال CDP حي
  (`http://127.0.0.1:9222`)، وبث لقطات العرض الحي، وتفاعل بالمحددات (نقر،
  كتابة)، وعارض سجلات كونسول CDP في الوقت الحقيقي.
- **تنسيق أشجار العمل**: إنشاء وإدارة أشجار git عمل معزولة لكل فرع، وتغيير
  المشروع النشط فورًا.
- **لوحة الأوامر (`⌘K`)**: تنقّل سريع بلوحة المفاتيح بين اللوحات والجلسات
  والسمات (داكن، فاتح، النظام).

## البدء السريع

### 1. المتطلبات والإعداد

```bash
npm install
npm run setup:core   # تنزيل ثنائي OpenCode المثبّت إلى src-tauri/bin
```

### 2. تشغيل تطبيق سطح المكتب

```bash
npm run dev          # يبدأ تطبيق Tauri + يشرف على النواة تلقائيًا
```

أو معاينة الويب:
```bash
npm run web          # Vite فقط — http://localhost:1420
```

### 3. بناء حزم التثبيت (Windows / macOS / Linux)

```bash
npm run dist         # ينزّل النواة المثبّتة ثم يبني حزم الإصدار
```

توضع النواتج في `src-tauri/target/release/bundle/`:

| النظام | الملفات |
|---|---|
| Windows | `.msi` و`.exe` (NSIS) |
| macOS | `.app` و`.dmg` (لكل معمارية مع `--target aarch64-apple-darwin` / `x86_64-apple-darwin`) |
| Linux | `.deb` و`.rpm` و`.AppImage` |

نواة OpenCode المثبّتة تُشحن **داخل** كل حزمة تثبيت (`bundle.externalBin`)،
فيثبّت المستخدم النهائي ملفًا واحدًا ولا يلمس طرفية أبدًا.

للتكرار السريع دون تغليف الإصدار: `npm run dist:debug`.

### 4. الإفراج للمستخدمين (أمر واحد لكل الأنظمة الثلاثة)

تبني أنظمة التشغيل حزم التثبيت في CI عند دفع وسم إصدار:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

يبني GitHub Actions (`.github/workflows/release.yml`) حزم Windows
`.msi`/`.exe`، وmacOS `.dmg` (Apple Silicon + Intel)، وLinux
`.deb`/`.rpm`/`.AppImage`، ثم يرفقها جميعًا بإصدار GitHub Release. هذا أقرب
ما يكون إلى `npm install -g` لتطبيق سطح مكتب: ينقر المستخدم رابطًا واحدًا في
صفحة Releases.

> ملاحظة: `npm install -g` لأدوات سطر الأوامر. BuzzAgent تطبيق واجهة رسومية
> لسطح المكتب، فيُوزَّع بحزم التثبيت؛ ولا يوجد مسار تثبيت عالمي.

### 5. التحقق والاختبارات

```bash
npm run typecheck    # فحص TypeScript الصارم
npm run lint         # ESLint 9
npm test             # مجموعة اختبارات Vitest (markdown, diff, client, store, UI)
cd src-tauri && cargo test   # اختبارات المشرف وgit والمتصفح في Rust
npm run test:integration     # من طرف إلى طرف مع OpenCode حي + مزوّد وهمي
```
