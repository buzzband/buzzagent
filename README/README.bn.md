# BuzzAgent — বাংলা (README.bn.md)

🌐 প্রজেক্ট ওয়েবসাইট: **https://b4zz.com/agent**

AI কোডিং এজেন্টদের জন্য ওপেন-সোর্স ভিজ্যুয়াল ওয়ার্কবেঞ্চ। এজেন্টের কোর
[OpenCode](https://github.com/anomalyco/opencode) (MIT); BuzzAgent তার
চারপাশের GUI ক্লায়েন্ট — অন্য কোনো এজেন্ট রানটাইম নয়।

> **এজেন্ট যা কিছু করে সবই দেখুন। মডেল, টুল, ব্রাউজার, MCP ও রিজনিং — লোকালি,
> শূন্য টেলিমেট্রি নিয়ে নিয়ন্ত্রণ করুন।**

## এটা কেন বানানো হলো

বাজার দুই ভাগে ভাগ হয়ে আছে:

**ভিজ্যুয়াল কিন্তু দুর্বল।** Cline, Kilo Code, Roo Code — ব্যবহারযোগ্য UI,
কিন্তু VS Code-এর ভেতরে বন্দি, টেলিমেট্রিসহ, আর দুর্বল এজেন্ট লুপ।

**শক্তিশালী কিন্তু অন্ধ।** OpenCode, Claude Code, Codex CLI, Oh My Pi —
মজবুত এজেন্ট, কিন্তু শুধুই টার্মিনাল। ভিজ্যুয়াল ডিফ নেই, ইন-অ্যাপ ব্রাউজার
নেই, ওয়ার্কস্পেস অর্কেস্ট্রেশন নেই।

ফাঁকটা হলো এমন একটা প্রোডাক্ট যেটা টার্মিনাল-এজেন্টের শক্তি **এবং** ভিজ্যুয়াল
নিয়ন্ত্রণ দুটোই দেয় — টেলিমেট্রি ছাড়া, ভেন্ডর লক-ইন ছাড়া।

BuzzAgent সেই প্রোডাক্ট। এটা এজেন্ট **নতুন করে লেখে না**। OpenCode নিজেই একটা
হেডলেস HTTP সার্ভার (`opencode serve`) — OpenAPI স্পেক, SSE ইভেন্ট স্ট্রিম আর
টাইপ-করা JS SDK সহ। তাদের TUI ওই সার্ভারেরই একটা ক্লায়েন্ট; তাদের IDE
প্লাগইন আরেকটা। BuzzAgent হলো তৃতীয় ক্লায়েন্ট: স্ট্যান্ডঅ্যালোন ডেস্কটপ GUI।

Kilo Code-এর CLI OpenCode-এর একটা **ফর্ক**, পরে সেটাকে VS Code এক্সটেনশন
(Cline বংশ) মুড়ে অ্যাকাউন্ট ও টেলিমেট্রি জুড়ে দেওয়া হয়েছে। আমরা সেই পথ
অনুসরণ করি না। ফর্ক মানে তাদের রক্ষণাবেক্ষণ খরচ মাথায় নেওয়া আর আপস্ট্রিম থেকে
বিচ্ছিন্ন হওয়া। ক্লায়েন্ট বানালে কোর OpenCode-এর নিয়মিত রিলিজের সঙ্গে সবসময়
আপ-টু-ডেট থাকে।

### OpenCode এখন নিজের GUI-ও দেয়

1.18 থেকে OpenCode রিপো `opencode-desktop-*` বিল্ড (Electron + SolidJS,
~120–150 MB) আর ব্রাউজার মোড (`opencode web`) দেয়। "OpenCode-এর ভিজ্যুয়াল
ক্লায়েন্ট" এখন **নিজে থেকেই আর কোনো পার্থক্য গড়ে না** — কোরের লেখকদের
নিজেরটাই আছে।

তবু যেটা আমাদের:

- **শূন্য টেলিমেট্রি — যাচাইযোগ্য সত্য।** তাদের ডেস্কটপ `@sentry/solid`
  যুক্ত করে এবং বিল্ড টাইমে `VITE_SENTRY_DSN` সেট থাকলে সেটা চালু করে
  (`packages/desktop/src/renderer/index.tsx`), সঙ্গে বিল্ডে
  `sentryVitePlugin`। আমাদের প্রসেসে কোনো ক্র্যাশ রিপোর্টার নেই, কোনো
  অ্যানালিটিক্স ডিপেন্ডেন্সিও নেই।
- **এজেন্ট লুপের ভেতরে ব্রাউজার** — কোড লেখে, ফলাফল খোলে, স্ক্রিনশট টুল
  রেজাল্ট হয়ে ফেরে, ঠিক করে। শুধু হেডলেস নয়: CDP দিয়ে চলমান Chrome-এর সঙ্গে
  যুক্তও হতে পারে, যাতে এজেন্ট সেই প্রোফাইলে কাজ করতে পারে যেখানে ইউজার
  আগেই লগ-ইন করা (`shell_exec`-এর মতোই পারমিশন-গেটেড)।
- **ওয়ার্কট্রি অর্কেস্ট্রেশন** — বিচ্ছিন্ন ব্রাঞ্চে একাধিক এজেন্ট সমান্তরালে,
  ভিজ্যুয়াল মনিটর সহ।
- **অ্যাকাউন্ট নেই, বান্ডেল-গেটওয়ে নেই।** Zen/Go ডিফল্ট পথ নেই।

পরিণতি: আমাদের GUI-র তুলনা হবে সরাসরি তাদেরটার সঙ্গে। এতে মানের মানদণ্ড
বাড়ে, এবং এই জন্যই মাইলফলক ১ হবে একটা সরু নির্ভরযোগ্য স্লাইস — বড়
ফিচার-ঝাড়ু নয়।

তাদের ডেস্কটপ থেকে দরকারি উদাহরণ:
`packages/desktop/src/main/sidecar.ts` `OPENCODE_SERVER_PASSWORD` দিয়ে
সার্ভার চালায় — র‍্যান্ডম পোর্ট, CORS শুধু তাদের নিজের origin-এ সীমাবদ্ধ,
loopback `NO_PROXY`-তে ঢোকানো, সিস্টেম CA সার্টিফিকেট লোড করা। আমরা সেই
হার্ডেনিংই নিই।

## আর্কিটেকচার

```
┌─────────────────────────────────────────────────────────┐
│  BuzzAgent (Tauri + React)                              │
│                                                         │
│  ভিজ্যুয়াল লেয়ার  ──HTTP + SSE──►  opencode serve        │
│  চ্যাট · ডিফ · ফাইল ·          (sidecar বাইনারি,          │
│  প্রোভাইডার · পারমিশন ·         পিন করা ভার্সন)            │
│  ওয়ার্কট্রি                                              │
│                                                         │
│  Rust লেয়ার                                              │
│  · কোর প্রসেসের তত্ত্বাবধান                                │
│  · এমবেডেড ব্রাউজার (CDP) ──কোর টুল হিসেবে নিবন্ধিত──      │
│  · git worktree অর্কেস্ট্রেশন                              │
└─────────────────────────────────────────────────────────┘
```

- **কোর = OpenCode।** টুল লুপ, নেটিভ ফাংশন কলিং, স্ট্রিমিং, সেশন ও রিজিউম,
  কমপ্যাকশন, পারমিশন, LSP, MCP, grep/glob/symbols, AGENTS.md, স্কিল, স্ল্যাশ
  কমান্ড, 75+ প্রোভাইডার, OAuth। এগুলোর কিছুই আমরা নতুন করে লিখি না।
- **GUI = BuzzAgent।** টুল-কল কার্ডসহ চ্যাট, ভিজ্যুয়াল ডিফ, ফাইল ট্রি,
  পারমিশন ইনবক্স, রোল-ভিত্তিক মডেল/এফোর্ট কন্ট্রোল, ওয়ার্কট্রি মনিটর।
- **কোরে নেই এমন নেটিভ এক্সট্রা।** এজেন্ট লুপে এমবেডেড ব্রাউজার; বিচ্ছিন্ন
  git worktree-তে সমান্তরাল এজেন্ট।

ফ্রন্টএন্ড কোরের সঙ্গে **সরাসরি** HTTP ও SSE-তে কথা বলে — **পিন করা** OpenAPI
স্পেক (`GET /doc`) থেকে তৈরি `@opencode-ai/sdk` দিয়ে। Rust এজেন্ট ট্রাফিকের
প্রক্সি নয়। Rust শুধু:

1. `opencode serve` চালায় ও তত্ত্বাবধান করে (র‍্যান্ডম পোর্ট, পাসওয়ার্ড,
   হেলথ চেক)।
2. সেই নেটিভ টুলগুলো দেয় যেগুলো কোর নিজে পারে না (ব্রাউজার, ওয়ার্কট্রি)।

এই ভাগটাই OpenCode ভেতরে ভেতরে ব্যবহার করে: TUI ক্লায়েন্ট, সার্ভার রানটাইম।

## কেন Tauri (এবং এর দাম)

হট পাথ — স্ট্রিমিং টোকেন, টুল কার্ড, ডিফ — webview থেকে লোকাল কোরে
HTTP/SSE-তে সরাসরি যায়, Tauri IPC **দিয়ে যায় না**, তাই শেলের IPC থ্রুপুট
ক্রিটিক্যাল পাথে পড়ে না। ফলে ডেস্কটপ শেল পারফরম্যান্সের নয়, প্যাকেজিং ও
নেটিভ-ক্ষমতার সিদ্ধান্ত।

Tauri, কারণ:

- আমাদের যেহেতু নেটিভ লেয়ার লাগবেই — প্রসেস তত্ত্বাবধান, CDP ব্রাউজার কন্ট্রোল
  আর git worktree-র জন্য — সেই কোড আছে, টেস্টও পাস করে।
- Electron-এ গেলে আমরা ঠিক OpenCode-এর নিজের ডেস্কটপের (Electron + SolidJS +
  sidecar) স্ট্যাকে চলে যাব, যেখানে কোর লেখকদের বাড়তি সুবিধা আছে আর আমাদের
  কোনো পার্থক্য থাকবে না।
- তাদের Electron টেমপ্লেট Sentry ইন্টিগ্রেশন নিয়ে আসে। আমাদের নিয়ন্ত্রণের
  স্ট্যাকে "টেলিমেট্রি নেই" দাবিটা সত্য রাখা সহজ।
- বান্ডল সাইজ এখানে দুর্বল যুক্তি: শুধু কোর বাইনারিই ~57 MB, তাই 5 MB বনাম
  120 MB শেল নির্ণায়ক নয়।

আসল খরচ, সোজাসুজি:

- **তিনটে আলাদা webview।** Windows-এ WebView2 (Chromium, সেলফ-আপডেটিং),
  macOS-এ WKWebView, Linux-এ `webkit2gtk`। Tauri-র নিজের টেবিল অনুযায়ী
  `webkit2gtk` 2.36 ≈ Safari 16, পুরোনো ডিস্ট্রো আরও পিছিয়ে। Linux-ই দুর্বলতম
  টার্গেট এবং রেন্ডারিং বাগ প্রথম সেখানেই দেখা দেবে। প্রতিকার: রক্ষণশীল CSS,
  নতুন ঢেউয়ের Web API নয়, আসল `webkit2gtk`-তে টেস্ট।
- **এক উইন্ডোতে একাধিক webview Tauri-র `unstable` ফ্ল্যাগের আড়ালে।** ব্রাউজার
  প্যানেলের জন্য গুরুত্বপূর্ণ: দ্বিতীয় লাইভ webview এমবেড না করে CDP +
  স্ক্রিনশট/স্ট্রিম UI-তে দেখানো ভালো, বা আলাদা উইন্ডো মেনে নেওয়া।
- Rust বিল্ড টাইম আর Electron-এর চেয়ে ছোট প্লাগইন ইকোসিস্টেম।

### বিবেচিত বিকল্প

| বিকল্প | রায় |
|---|---|
| **Electron** | সবচেয়ে অনুমানযোগ্য UX: সব জায়গায় এক Chromium, সেরা ইকোসিস্টেম, সহজ devtools। ডিফল্ট হিসেবে বাতিল — কারণ এটা হুবহু OpenCode ডেস্কটপের স্ট্যাক, আর নেটিভ কোড তবু node অ্যাডঅন দিয়েই লিখতে হবে। `webkit2gtk` বাগ অনিয়ন্ত্রণীয় হলে সৎ ফলব্যাক। |
| **Go + Wails** | Tauri-র মতোই সিস্টেম-webview মডেল, তাই একই `webkit2gtk` সমস্যা, সঙ্গে আছে এমন Rust কোড ছেড়ে দেওয়া। Go এখানে কিছুই কেনে না: কোর Go-তে না, আর আমাদের নেটিভ কাজ (CDP, worktree, তত্ত্বাবধান) Go-তে সহজ হয় না। |
| **খাঁটি Rust GUI** (egui, Iced, GPUI, Dioxus native, Slint) | webview-বাগ শ্রেণি মুছে যায়, আসল নেটিভ পারফরম্যান্স। কিন্তু চ্যাট, markdown, সিনট্যাক্স হাইলাইট, ডিফ ভিউ, ফাইল ট্রি সব হাতে বানাতে হবে — ঠিক যেখানে কোড-এজেন্ট GUI-কে বিচারা হয়। বহু-বছরের ঘুরপথ, আর ব্রাউজার প্যানেল প্রায় অসম্ভব। v1-এর জন্য অবাস্তব। |
| **শুধু Web UI** (নিজের ফ্রন্টএন্ড ব্রাউজারে সার্ভ) | সবচেয়ে সস্তা, আর সত্যিই দরকারি গৌণ টার্গেট — কিন্তু OpenCode আগেই `opencode web` দেয়, আর ব্রাউজার ট্যাব নেটিভ মেনু, worktree বা এমবেডেড ব্রাউজার রাখতে পারে না। পরে অতিরিক্ত মোড হিসেবে ভালো, প্রোডাক্ট হিসেবে নয়। |
| **Flutter / .NET / Qt** | নেটিভ-মানের উইজেট, কিন্তু React পুনঃব্যবহার নেই, আর "markdown + ডিফ + কোড রেন্ডার" ইকোসিস্টেম ওয়েবের চেয়ে দুর্বল। বড় রিরাইট, কৌশলগত লাভ নেই। |
| **VS Code এক্সটেনশন** | চেনা আর সস্তা, কিন্তু এটাই Cline/Kilo-র সেই বাক্স যার বিরুদ্ধে আমরা স্পষ্টভাবে দাঁড়াই, আর স্ট্যান্ডঅ্যালোন/টেলিমেট্রিহীন গল্পটাও মরে যায়। |

সিদ্ধান্ত: **এখন Tauri + React**, Electron নথিভুক্ত ফলব্যাক — শুধু Linux webview
ত্রুটি অমোঘ প্রমাণিত হলে। UI-কে কোরের সাধারণ HTTP/SSE ক্লায়েন্ট রাখাই ওই
ফলব্যাককে সস্তা করে — শেল বদলানো যায় কারণ এজেন্ট লজিক তাতে বাস করে না।

### কোর হিসেবে Oh My Pi কেন নয়

[oh-my-pi](https://github.com/can1357/oh-my-pi) (MIT, ~30k স্টার) একটা মজবুত
এজেন্ট — কোথাও OpenCode-এর চেয়ে গভীর: লুপে LSP, DAP, hashline এডিট, বিশাল
নেটিভ Rust লেয়ার, `pr://`/`issue://`/`agent://` URI স্কিম, মডেল ফলব্যাক
চেইন। তবু *এই প্রোডাক্টের* জন্য এটা ভুল কোর:

- **HTTP সার্ভার নেই।** চারটে পৃষ্ঠ: TUI, ওয়ান-শট প্রম্পট, ইন-প্রসেস Node SDK,
  আর **stdio**-তে `--mode rpc` / `acp`। ব্রাউজার stdio বলতে পারে না, তাই
  Rust-কে প্রতিটা মেসেজের প্রক্সি হতে হবে — যে লেয়ারটা আমরা জানতে জানতে বাদ
  দিয়েছি — আর তাদের RPC-তে লাগে ম্যানুয়াল 1 MiB ফ্রেম চাংকিং ও প্রোটোকল
  নেগোশিয়েশন। OpenAPI স্পেক নেই, তাই জেনারেটেড ক্লায়েন্টও নেই।
- **বন্ধ করা যায় না এমন টেলিমেট্রি।** স্থায়ী ইনস্টল UUID
  (`~/.omp/install-id`, তাদের `docs/install-id.md`-এ নথিভুক্ত) এজেন্ট স্টেট
  মুছে ফেললেও টেকে, আর এটা — অন্যদের পাশাপাশি — এমন এক auth-broker ব্যবহার
  রিপোর্টকে খাওয়ায় যাতে হোস্টনেমও যায়, সঙ্গে auto-QA পুশ। ওটা সরানো মানে
  তাদের রানটাইম ফর্ক করা — অন্যের কোর নেওয়ার সার কথাই শেষ।
- **জায়গাটা আগেই দখল হয়ে গেছে:** `gooey-pi`, `pi-desktop`, `ohmypi-craft`,
  `ompweb` আগে থেকেই OMP GUI।

কোনো দিন দ্বিতীয় ব্যাকএন্ড যোগ করলে সেটা হবে **ACP** দিয়ে — শেয়ার্ড
প্রোটোকল — অ্যাডাপ্টার ইন্টারফেসের পেছনে, আর শুধুমাত্র OpenCode স্লাইস মজবুত
হওয়ার পরে।

## ইন্টারফেসের মানই প্রোডাক্ট

উপরের সব প্লাম্বিং। BuzzAgent বেছে নেওয়ার কারণ ইন্টারফেস, তাই তাকে "চলছে"
নয়, একটা মানদণ্ডে বিচারা হয়: নেটওয়ার্কে কিছু আটকায় না, স্ট্রিমিংয়ে 60 fps,
লেআউট শিফট নেই, কীবোর্ড-ফার্স্ট, সিনট্যাক্স হাইলাইটসহ সত্যিকার side-by-side
ডিফ, লম্বা সেশন ভার্চুয়ালাইজড, ভাবা-ফেলা খালি/এরর/অফলাইন স্টেট, ডার্ক **এবং**
লাইট থিম, আর প্রকৃত অ্যাক্সেসিবিলিটি (ফোকাস, কনট্রাস্ট, মেসেজ স্ট্রিমের জন্য
স্ক্রিন-রিডার সাপোর্ট)।

পূর্ণ মানদণ্ড, নির্বাচিত ফ্রন্টএন্ড স্ট্যাক (React 19, Tailwind 4, Radix,
Shiki, CodeMirror 6, TanStack Virtual, cmdk) আর ডিপেন্ডেন্সি যোগের নিয়ম
PLAN.md-এ।

## একটা সেটিং কীভাবে কোরে পৌঁছায়

UI কোর স্টেটের দ্বিতীয় কপি রাখে না। উদাহরণ — ইউজার API key পেস্ট করল:

1. মডেলস প্যানেল `GET /provider/auth` ডাকে। ফর্ম কোরের ফেরত পাঠানো schema
   থেকে রেন্ডার হয় (API key, OAuth, ডিভাইস ফ্লো, …)।
2. সেভে UI `PUT /auth/:id` ডাকে। কোর `~/.local/share/opencode/auth.json`
   লেখে। key না আমাদের স্টোরে থাকে না `localStorage`-এ।
3. Base URL, মডেল হোয়াইটলিস্ট, `share: "disabled"` যায় `PATCH /config`
   দিয়ে।
4. মডেল পিকার হলো `GET /config/providers` / `GET /provider`।
5. এক টার্নের মডেল হলো `POST /session/:id/message`-এর ফিল্ড (`model`,
   `agent`)। "রোল-ভিত্তিক রাউটার" মানে আমাদের UI এই ফিল্ডগুলোই বাছে — 75
   প্রোভাইডারের সামনে আরেকটা HTTP ক্লায়েন্ট নয়।

OAuth প্রোভাইডার (Claude Pro, Copilot, GitLab Duo, DigitalOcean) ব্যবহার করে
`POST /provider/{id}/oauth/authorize` → সিস্টেম ব্রাউজার →
`POST /provider/{id}/oauth/callback`। আমাদের দিকে কোনো প্রোভাইডার-নির্দিষ্ট
কোড নেই।

দুই স্টোর আবার আলাদা হলে এজেন্ট চালুই হবে না। কোরই কনফিগ, সেশন, ডিফ ও
পারমিশনের একমাত্র মালিক।

## আমরা কী বানাই, কী বানাই না

**আমরা লিখি না:** প্রোভাইডার, OAuth, টুল লুপ, স্ট্রিমিং, সেশন, কমপ্যাকশন,
পারমিশন ইঞ্জিন, LSP, MCP, grep/glob/symbols, AGENTS.md, স্ল্যাশ কমান্ড,
স্কিল, টুডু।

**আমরা লিখি:** পুরো ভিজ্যুয়াল লেয়ার; কোর টুল হিসেবে এমবেডেড ব্রাউজার;
ওয়ার্কট্রি অর্কেস্ট্রেশন; পারমিশন ইনবক্স; ভিজ্যুয়াল মডেল/এফোর্ট রাউটার;
প্রসেস তত্ত্বাবধান; প্যাকেজিং।

**আমরা OpenCode ফর্ক করি না** যতক্ষণ না কোনো ভার্টিক্যাল স্লাইস প্রমাণ করে
কোর সিমান্টিক্স (সিস্টেম প্রম্পট, টুল আচরণ, ডিফ স্টেজিং) বদলাতেই হবে। সেই
সিদ্ধান্ত প্রমাণের ভিত্তিতে হয়, মাইলফলক ১-এর পরে — আগে থেকে নয়।

## শূন্য টেলিমেট্রি — যাচাইকৃত

অডিট (মাইলফলক ০) সম্পন্ন ও ব্যবহারিকভাবে যাচাইকৃত। পূর্ণ পুনরুৎপাদন ধাপ
[docs/telemetry-audit.md](./docs/telemetry-audit.md)-এ।

- **তৃতীয় পক্ষের টেলিমেট্রি শূন্য।** কোর বাইনারিতে Sentry, PostHog, Segment,
  Mixpanel, Datadog বা কোনো অ্যানালিটিক্স SDK নেই।
- **আউটবাউন্ড নেটওয়ার্ক কল জোর করে বন্ধ।** কথোপকথন শেয়ারিং
  (`"share": "disabled"`), সেলফ-আপডেট (`"autoupdate": false`) আর Zen ছোট
  মডেল — সব জোর করা অন-ডিস্ক কনফিগ দিয়ে বন্ধ।
- **পৃথক পরিবেশ।** সব স্টেট, ক্যাশ, db ও লগ অ্যাপ ডেটা ডিরেক্টরির ভেতরে
  (`XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`)।
- **নিরাপত্তা।** র‍্যান্ডম ৬৪-অক্ষরের পাসওয়ার্ডসহ HTTP Basic প্রমাণীকরণ, শুধু
  `127.0.0.1`-এ বাইন্ড।

## বর্তমান অবস্থা

BuzzAgent নতুন করে বানানো এবং পুরোপুরি কার্যকর:
- **কোর সুপারভাইজার (Rust)**: স্বয়ংক্রিয় প্রসেস ব্যবস্থাপনা, র‍্যান্ডম পোর্ট,
  পাসওয়ার্ড জেনারেশন, হেলথ চেক, পরিবেশ বিচ্ছিন্নকরণ, লুপব্যাক `NO_PROXY`
  বাইপাস, বেরোনোর সময় পরিচ্ছন্ন টিয়ারডাউন।
- **ডাইরেক্ট HTTP + SSE ক্লায়েন্ট**: OpenCode কোর API-তে সরাসরি সংযোগ, ফ্রেম-
  বাউন্ড্রি স্থিতিস্থাপক ইভেন্ট স্ট্রিম পার্সিং, সেশন ব্যবস্থাপনা, মাল্টি-টার্ন
  মেসেজিং, পারমিশন গেটিং।
- **ভিজ্যুয়াল ওয়ার্কবেঞ্চ UI**: রিয়েল-টাইম স্ট্রিমিং চ্যাট, ঝিকমিক-বিহীন
  markdown, সিনট্যাক্স-হাইলাইটেড কোড ব্লক (Shiki), পরিদর্শনযোগ্য টুল কার্ড
  (অবস্থা/সময়/ত্রুটি সহ), পারমিশন ডায়ালগ।
- **ভিজ্যুয়াল ডিফ প্যানেল**: রিয়েল-টাইম git পরিবর্তন ভিউয়ার, শব্দ-স্তরের
  মার্ক (`+`/`−`), এক ক্লিকে ফাইল রিভার্ট।
- **ইন-অ্যাপ ব্রাউজার প্যানেল**: হেডলেস Chrome অটোমেশন ও লাইভ CDP অ্যাটাচ
  (`http://127.0.0.1:9222`), লাইভ ভিউপোর্ট স্ক্রিনশট স্ট্রিম, সিলেক্টর
  ইন্টারঅ্যাকশন (ক্লিক, টাইপ), রিয়েল-টাইম CDP কনসোল লগ ভিউয়ার।
- **ওয়ার্কট্রি অর্কেস্ট্রেশন**: ব্রাঞ্চ-ভিত্তিক বিচ্ছিন্ন git worktree তৈরি ও
  ব্যবস্থাপনা, চলতি প্রজেক্ট মুহূর্তেই বদলানো।
- **কমান্ড প্যালেট (`⌘K`)**: প্যানেল, সেশন ও থিমে (ডার্ক, লাইট, সিস্টেম) কীবোর্ড-
  ফার্স্ট দ্রুত নেভিগেশন।

## দ্রুত শুরু

### 1. প্রয়োজনীয়তা ও সেটআপ

```bash
npm install
npm run setup:core   # পিন করা OpenCode বাইনারি src-tauri/bin-এ ডাউনলোড
```

### 2. ডেস্কটপ অ্যাপ চালান

```bash
npm run dev          # Tauri ডেস্কটপ অ্যাপ + কোরের স্বয়ংক্রিয় তত্ত্বাবধান
```

অথবা Web প্রিভিউ:
```bash
npm run web          # শুধু Vite — http://localhost:1420
```

### 3. ইনস্টলার বানান (Windows / macOS / Linux)

```bash
npm run dist         # পিন করা কোর ডাউনলোড, তারপর রিলিজ ইনস্টলার বিল্ড
```

আর্টিফ্যাক্ট পড়ে `src-tauri/target/release/bundle/`-এ:

| OS | ফাইল |
|---|---|
| Windows | `.msi`, NSIS `.exe` |
| macOS | `.app`, `.dmg` (আর্কিটেকচার-ভিত্তিক: `--target aarch64-apple-darwin` / `x86_64-apple-darwin`) |
| Linux | `.deb`, `.rpm`, `.AppImage` |

পিন করা OpenCode কোর **প্রতিটা** ইনস্টলারের ভেতরেই যায় (`bundle.externalBin`),
ফলে শেষ ইউজার একটা ফাইল ইনস্টল করে আর টার্মিনাল ছোঁয়ই না।

রিলিজ বান্ডলিং ছাড়া দ্রুত পুনরাবৃত্তি: `npm run dist:debug`।

### 4. ইউজারদের কাছে রিলিজ (তিন OS-এর জন্য এক কমান্ড)

ভার্সন ট্যাগ পুশ করলে CI সব OS-এর ইনস্টলার বানায়:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

GitHub Actions (`.github/workflows/release.yml`) Windows `.msi`/`.exe`, macOS
`.dmg` (Apple Silicon + Intel) আর Linux `.deb`/`.rpm`/`.AppImage` বানিয়ে সব
GitHub Release-এ যুক্ত করে। ডেস্কটপ অ্যাপের জন্য এটাই `npm install -g`-র
সবচেয়ে কাছের সমতুল্য: ইউজার Releases পেজে একটা লিংকে ক্লিক করে।

> লক্ষ করুন: `npm install -g` CLI টুলের জন্য। BuzzAgent ডেস্কটপ GUI অ্যাপ,
> বিতরণ হয় ইনস্টলার দিয়ে; গ্লোবাল-ইনস্টল পথ নেই।

### 5. যাচাই ও টেস্ট

```bash
npm run typecheck    # TypeScript কড়া চেক
npm run lint         # ESLint 9
npm test             # Vitest ইউনিট স্যুট (markdown, diff, client, store, UI)
cd src-tauri && cargo test   # Rust সুপারভাইজার, git, ব্রাউজার টেস্ট
npm run test:integration     # লাইভ OpenCode + mock প্রোভাইডারে এন্ড-টু-এন্ড
```
