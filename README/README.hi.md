# BuzzAgent — हिन्दी (README.hi.md)

🌐 प्रोजेक्ट वेबसाइट: **https://b4zz.com/agent**

AI कोडिंग एजेंटों के लिए ओपन-सोर्स विज़ुअल वर्कबेंच। एजेंट कोर
[OpenCode](https://github.com/anomalyco/opencode) (MIT) है; BuzzAgent उसके
चारों ओर का GUI क्लाइंट है — कोई और एजेंट रनटाइम नहीं।

> **एजेंट जो कुछ भी करता है, सब देखें। मॉडल, टूल, ब्राउज़र, MCP और रीज़निंग —
> स्थानीय रूप से, शून्य टेलीमेट्री के साथ नियंत्रित करें।**

## यह क्यों बनाया गया

बाज़ार दो हिस्सों में बँटा है:

**विज़ुअल पर कमज़ोर।** Cline, Kilo Code, Roo Code — ठीक-ठाक UI, लेकिन VS Code
में बंद, टेलीमेट्री के साथ, और कमज़ोर एजेंट लूप।

**ताक़तवर पर अंधा।** OpenCode, Claude Code, Codex CLI, Oh My Pi — मज़बूत
एजेंट, लेकिन सिर्फ़ टर्मिनल। कोई विज़ुअल डिफ़ नहीं, कोई इन-ऐप ब्राउज़र नहीं,
कोई वर्कस्पेस ऑर्केस्ट्रेशन नहीं।

खाई में वह उत्पाद है जो टर्मिनल-एजेंट की ताक़त **और** विज़ुअल नियंत्रण दोनों
दे — बिना टेलीमेट्री, बिना वेंडर लॉक-इन।

BuzzAgent वही उत्पाद है। यह एजेंट को **फिर से नहीं लिखता**। OpenCode खुद एक
हेडलेस HTTP सर्वर है (`opencode serve`) — OpenAPI स्पेसिफ़िकेशन, SSE इवेंट
स्ट्रीम और टाइप किया हुआ JS SDK के साथ। उनका TUI उस सर्वर का एक क्लाइंट है;
उनके IDE प्लगइन दूसरे। BuzzAgent तीसरा क्लाइंट है: एक स्टैंडअलोन डेस्कटॉप
GUI।

Kilo Code की CLI OpenCode का **फ़ोर्क** है, फिर VS Code एक्सटेंशन (Cline
वंश) के रूप में लिपटा हुआ, अकाउंट और टेलीमेट्री सहित। हम वह रास्ता नहीं चुनते।
फ़ोर्क उनकी रखरखाव लागत उठा लेता है और हमें अपस्ट्रीम से काट देता है। क्लाइंट
बनाने से कोर OpenCode के लगातार रिलीज़ होते रहने पर हमेशा ताज़ा रहता है।

### OpenCode अब अपना GUI भी देता है

1.18 से OpenCode रिपॉज़िटरी `opencode-desktop-*` बिल्ड (Electron + SolidJS,
~120–150 MB) और ब्राउज़र मोड (`opencode web`) देती है। "OpenCode का विज़ुअल
क्लाइंट" अपने आप में **अब कोई अलग बात नहीं** — कोर लेखकों का अपना है।

फिर भी हमारा क्या है:

- **शून्य टेलीमेट्री — एक सत्यापित तथ्य।** उनका डेस्कटॉप `@sentry/solid`
  जोड़ता है और बिल्ड समय पर `VITE_SENTRY_DSN` सेट होने पर उसे इनिशियलाइज़ करता
  है (`packages/desktop/src/renderer/index.tsx`), साथ में बिल्ड में
  `sentryVitePlugin`। हमारी प्रक्रिया में न कोई क्रैश रिपोर्टर है, न कोई
  एनालिटिक्स डिपेंडेंसी।
- **एजेंट लूप में ब्राउज़र** — कोड लिखो, नतीजा खोलो, स्क्रीनशॉट टूल रिज़ल्ट
  के रूप में वापस भेजो, सुधारो। सिर्फ़ हेडलेस नहीं: CDP से चल रहे Chrome से
  भी जुड़ सकता है, ताकि एजेंट उस प्रोफ़ाइल पर काम करे जिसमें यूज़र पहले से
  लॉग-इन है (`shell_exec` की तरह परमिशन-गेटेड)।
- **वर्कट्री ऑर्केस्ट्रेशन** — कई एजेंट अलग-अलग ब्रांच पर समानांतर, विज़ुअल
  मॉनिटर के साथ।
- **कोई अकाउंट नहीं, कोई बंडल गेटवे नहीं।** Zen/Go डिफ़ॉल्ट रास्ता नहीं।

नतीजा: हमारे GUI की तुलना सीधे उनके डेस्कटॉप से होगी। इससे गुणवत्ता का
स्तर बढ़ता है, और यही कारण है कि मील का पत्थर 1 चौड़ा फ़ीचर-स्वीप नहीं, बल्कि
एक संकरा भरोसेमंद स्लाइस है।

उनके डेस्कटॉप से एक उपयोगी उदाहरण:
`packages/desktop/src/main/sidecar.ts` सर्वर को `OPENCODE_SERVER_PASSWORD`
के साथ शुरू करता है — रैंडम पोर्ट, CORS सिर्फ़ अपने renderer ओरिजिन तक सीमित,
लूपबैक `NO_PROXY` में डाला गया, और सिस्टम CA सर्टिफ़िकेट लोड। हम वही हार्डनिंग
अपनाते हैं।

## आर्किटेक्चर

```
┌─────────────────────────────────────────────────────────┐
│  BuzzAgent (Tauri + React)                              │
│                                                         │
│  विज़ुअल लेयर   ──HTTP + SSE──►  opencode serve           │
│  चैट · डिफ़ · फ़ाइलें ·        (sidecar बाइनरी,             │
│  प्रोवाइडर · परमिशन ·        पिन किया वर्शन)              │
│  वर्कट्री                                                │
│                                                         │
│  Rust लेयर                                               │
│  · कोर प्रोसेस की देखरेख                                  │
│  · एम्बेडेड ब्राउज़र (CDP) ──कोर टूल के रूप में──           │
│  · git worktree ऑर्केस्ट्रेशन                             │
└─────────────────────────────────────────────────────────┘
```

- **कोर = OpenCode।** टूल लूप, नेटिव फ़ंक्शन कॉलिंग, स्ट्रीमिंग, सेशन और
  रिज़्यूम, कॉम्पैक्शन, परमिशन, LSP, MCP, grep/glob/symbols, AGENTS.md,
  स्किल्स, स्लैश कमांड, 75+ प्रोवाइडर, OAuth। हम इनमें से कुछ भी नहीं
  लिखते।
- **GUI = BuzzAgent।** टूल-कॉल कार्ड वाली चैट, विज़ुअल डिफ़, फ़ाइल ट्री,
  परमिशन इनबॉक्स, भूमिका-अनुसार मॉडल/एफ़र्ट कंट्रोल, वर्कट्री मॉनिटर।
- **कोर में न होने वाली नेटिव चीज़ें।** एजेंट लूप में एम्बेडेड ब्राउज़र;
  अलग git worktree में समानांतर एजेंट।

फ्रंटएंड कोर से सीधे HTTP और SSE पर बात करता है, **पिन किए** OpenAPI स्पेस
(`GET /doc`) से बने `@opencode-ai/sdk` से। Rust एजेंट ट्रैफ़िक का प्रॉक्सी
नहीं है। Rust सिर्फ़:

1. `opencode serve` को शुरू करता और देखरेख करता है (रैंडम पोर्ट, पासवर्ड,
   हेल्थ चेक)।
2. वे नेटिव टूल देता है जो कोर खुद नहीं कर सकता (ब्राउज़र, worktree)।

यही बँटवारा OpenCode भी भीतर उपयोग करता है: TUI क्लाइंट है, सर्वर रनटाइम।

## क्यों Tauri (और इसकी कीमत)

हॉट पाथ — स्ट्रीमिंग टोकन, टूल कार्ड, डिफ़ — webview से सीधे HTTP/SSE पर
लोकल कोर तक जाता है, Tauri IPC से **नहीं** गुज़रता, इसलिए शेल की IPC थ्रूपुट
क्रिटिकल पाथ पर नहीं है। इससे डेस्कटॉप शेल पैकेजिंग और नेटिव-क्षमता का निर्णय
बनता है, परफ़ॉर्मेंस का नहीं।

Tauri, क्योंकि:

- हमें वैसे भी नेटिव लेयर चाहिए — प्रोसेस देखरेख, CDP ब्राउज़र कंट्रोल और git
  worktree के लिए; वह कोड मौजूद है और उसके टेस्ट पास हैं।
- Electron पर जाना = OpenCode के अपने डेस्कटॉप (Electron + SolidJS +
  sidecar) का हूबहू स्टैक, जहाँ कोर लेखकों को बढ़त है और हमारे पास कोई
  डिफ़रेंशिएटर नहीं बचता।
- उनका Electron टेम्पलेट Sentry इंटीग्रेशन लेकर आता है। हमारे नियंत्रण वाले
  स्टैक पर "कोई टेलीमेट्री नहीं" का दावा सच रखना आसान है।
- बंडल साइज़ यहाँ कमज़ोर तर्क है: कोर बाइनरी अकेला ~57 MB है, तो 5 MB बनाम
  120 MB शेल फ़ैसलाकुन नहीं।

असली कीमत, साफ़ शब्दों में:

- **तीन अलग webview।** Windows पर WebView2 (Chromium, सेल्फ़-अपडेटिंग),
  macOS पर WKWebView, Linux पर `webkit2gtk`। Tauri की अपनी तालिका के अनुसार
  `webkit2gtk` 2.36 ≈ Safari 16, और पुराने डिस्ट्रो और पीछे हैं। Linux सबसे
  कमज़ोर टारगेट है और रेंडरिंग बग पहले वहीं दिखेंगे। बचाव: रूढ़िवादी CSS, नए
  छोर के Web API नहीं, असली `webkit2gtk` पर टेस्ट।
- **एक विंडो में कई webview Tauri के `unstable` फ़्लैग के पीछे हैं।** ब्राउज़र
  पैनल के लिए मायने रखता है: दूसरा लाइव webview एम्बेड करने के बजाय CDP +
  स्क्रीनशॉट/स्ट्रीम UI में दिखाना बेहतर, या अलग विंडो स्वीकार करना।
- Rust बिल्ड समय और Electron से छोटा प्लगइन इकोसिस्टम।

### विकल्प जिन पर विचार हुआ

| विकल्प | निर्णय |
|---|---|
| **Electron** | सबसे प्रेडिक्टेबल UX: हर जगह एक Chromium, सबसे बड़ा इकोसिस्टम, आसान devtools। डिफ़ॉल्ट के रूप में खारिज — यही OpenCode डेस्कटॉप का हूबहू स्टैक है, और नेटिव कोड फिर भी node ऐडऑन से लिखना पड़ेगा। ईमानदार फ़ॉलबैक अगर `webkit2gtk` बग अनियंत्रित हो जाएँ। |
| **Go + Wails** | Tauri जैसा ही सिस्टम-webview मॉडल, वही `webkit2gtk` समस्या, और मौजूदा Rust कोड का नुक़सान। Go यहाँ कुछ नहीं देता: कोर Go में नहीं है, और हमारा नेटिव काम (CDP, worktree, प्रोसेस देखरेख) Go में आसान नहीं होता। |
| **शुद्ध Rust GUI** (egui, Iced, GPUI, Dioxus native, Slint) | webview-बग वर्ग खत्म, असली नेटिव परफ़ॉर्मेंस। पर चैट, markdown, सिंटैक्स हाइलाइटिंग, डिफ़ व्यू और फ़ाइल ट्री सब हाथ से बनाने पड़ेंगे — वही सतह जहाँ कोड-एजेंट GUI को आँका जाता है। बहु-वर्षीय चक्कर, और ब्राउज़र पैनल लगभग असंभव। v1 के लिए अव्यावहारिक। |
| **सिर्फ़ Web UI** (अपना फ्रंटएंड सर्व करके ब्राउज़र में) | सबसे सस्ता, और सच में उपयोगी द्वितीय लक्ष्य — पर OpenCode पहले से `opencode web` देता है, और ब्राउज़र टैब नेटिव मेनू, worktree या एम्बेडेड ब्राउज़र नहीं रख सकता। बाद में अतिरिक्त मोड के लिए ठीक, उत्पाद के रूप में नहीं। |
| **Flutter / .NET / Qt** | नेटिव-स्तर के विजेट, पर React पुन: उपयोग नहीं, और "markdown + डिफ़ + कोड रेंडर" के लिए इकोसिस्टम वेब से कमज़ोर। बड़ा रीराइट, कोई रणनीतिक लाभ नहीं। |
| **VS Code एक्सटेंशन** | परिचित और सस्ता, पर यही Cline/Kilo की डिब्बाबंदी है जिसके ख़िलाफ़ हम स्पष्ट रूप से खड़े हैं, और स्टैंडअलोन/कोई-टेलीमेट्री-नहीं कहानी खत्म हो जाती है। |

निर्णय: **अभी Tauri + React**, Electron दस्तावेज़ीकृत फ़ॉलबैक — सिर्फ़ तब जब
Linux webview दोष अनुत्तरीय सिद्ध हों। UI को कोर का सादा HTTP/SSE क्लाइंट
रखना ही उस फ़ॉलबैक को सस्ता बनाता है — शेल बदलने योग्य है क्योंकि एजेंट लॉजिक
उसमें नहीं रहता।

### Oh My Pi कोर के रूप में क्यों नहीं

[oh-my-pi](https://github.com/can1357/oh-my-pi) (MIT, ~30k स्टार) एक मज़बूत
एजेंट है — कहीं OpenCode से गहरा: लूप में LSP, DAP, hashline एडिट, बड़ा नेटिव
Rust लेयर, `pr://`/`issue://`/`agent://` URI स्कीम, मॉडल फ़ॉलबैक चेन। फिर भी
*इस उत्पाद* के लिए यह ग़लत कोर है:

- **कोई HTTP सर्वर नहीं।** चार सतह हैं: TUI, वन-शॉट प्रॉम्प्ट, इन-प्रोसेस Node
  SDK, और **stdio** पर `--mode rpc` / `acp`। ब्राउज़र stdio नहीं बोल सकता,
  Rust को हर संदेश का प्रॉक्सी बनना पड़ेगा — वही लेयर जिसे हमने जानबूझकर हटाया
  — और उनके RPC में मैनुअल 1 MiB फ़्रेम चंकिंग व प्रोटोकॉल नेगोशिएशन चाहिए।
  OpenAPI स्पेस नहीं, तो जनरेटेड क्लाइंट भी नहीं।
- **टेलीमेट्री जिसे बंद नहीं किया जा सकता।** स्थायी इंस्टॉल UUID
  (`~/.omp/install-id`, उनके `docs/install-id.md` में दस्तावेज़ित) एजेंट स्टेट
  मिटाने पर भी बचा रहता है और — दूसरों के साथ — एक ऑथ-ब्रोकर उपयोग रिपोर्ट
  को खिलाता है जिसमें होस्टनाम भी जाता है, साथ में ऑटो-QA पुश। इसे हटाना =
  उनके रनटाइम का फ़ोर्क, जो किसी और के कोर को आधार बनाने की सारी बात खत्म कर
  देता है।
- **जगह पहले से ली गई है:** `gooey-pi`, `pi-desktop`, `ohmypi-craft`,
  `ompweb` पहले से OMP GUI हैं।

अगर कभी दूसरा बैकएंड जोड़ा जाए तो **ACP** से — साझा प्रोटोकॉल — एडॉप्टर
इंटरफ़ेस के पीछे, और केवल OpenCode स्लाइस मज़बूत होने के बाद।

## इंटरफ़ेस की गुणवत्ता ही उत्पाद है

ऊपर जो लिखा वह सारा प्लंबिंग है। BuzzAgent चुनने का कारण इंटरफ़ेस है, इसलिए
उसे "चल जाता है" नहीं, एक स्तर पर आँका जाता है: नेटवर्क पर कुछ ब्लॉक नहीं
होता, स्ट्रीमिंग में 60 fps, कोई लेआउट-शिफ़्ट नहीं, कीबोर्ड-फ़र्स्ट, सिंटैक्स
हाइलाइटिंग सहित असली side-by-side डिफ़, लंबे सेशन वर्चुअलाइज़्ड, सोचे-समझे
ख़ाली/त्रुटि/ऑफ़लाइन स्टेट, डार्क **और** लाइट थीम, और असली एक्सेसिबिलिटी
(फ़ोकस, कंट्रास्ट, मैसेज स्ट्रीम के लिए स्क्रीन-रीडर सपोर्ट)।

पूरा स्तर, चुना हुआ फ्रंटएंड स्टैक (React 19, Tailwind 4, Radix, Shiki,
CodeMirror 6, TanStack Virtual, cmdk) और डिपेंडेंसी जोड़ने के नियम
[PLAN.md](./PLAN.md#ui-quality-bar) में हैं।

## एक सेटिंग कोर तक कैसे पहुँचती है

UI कोर स्टेट की दूसरी कॉपी नहीं रखता। उदाहरण — यूज़र API key पेस्ट करता है:

1. मॉडल्स पैनल `GET /provider/auth` बुलाता है। फ़ॉर्म कोर के लौटाए schema से
   रेंडर होता है (API key, OAuth, डिवाइस फ़्लो, …)।
2. सेव पर UI `PUT /auth/:id` बुलाता है। कोर
   `~/.local/share/opencode/auth.json` लिखता है। key न हमारे स्टोर में रहती
   है, न `localStorage` में।
3. Base URL, मॉडल व्हाइटलिस्ट, `share: "disabled"` `PATCH /config` से जाते
   हैं।
4. मॉडल पिकर `GET /config/providers` / `GET /provider` है।
5. किसी टर्न का मॉडल `POST /session/:id/message` का फ़ील्ड है (`model`,
   `agent`)। "भूमिका-अनुसार राउटर" बस हमारा UI ये फ़ील्ड चुनता है — 75
   प्रोवाइडर के आगे कोई दूसरा HTTP क्लाइंट नहीं।

OAuth प्रोवाइडर (Claude Pro, Copilot, GitLab Duo, DigitalOcean)
`POST /provider/{id}/oauth/authorize` → सिस्टम ब्राउज़र →
`POST /provider/{id}/oauth/callback` उपयोग करते हैं। हमारी ओर कोई
प्रोवाइडर-विशिष्ट कोड नहीं।

अगर दो स्टोर कभी फिर अलग हुए, एजेंट शुरू ही नहीं होगा। कोर ही कॉन्फ़िग, सेशन,
डिफ़ और परमिशन का एकमात्र स्वामी है।

## हम क्या बनाते हैं और क्या नहीं

**हम नहीं लिखते:** प्रोवाइडर, OAuth, टूल लूप, स्ट्रीमिंग, सेशन, कॉम्पैक्शन,
परमिशन इंजन, LSP, MCP, grep/glob/symbols, AGENTS.md, स्लैश कमांड, स्किल्स,
टूडू।

**हम लिखते हैं:** पूरी विज़ुअल लेयर; कोर टूल के रूप में एम्बेडेड ब्राउज़र;
worktree ऑर्केस्ट्रेशन; परमिशन इनबॉक्स; विज़ुअल मॉडल/एफ़र्ट राउटर; प्रोसेस
देखरेख; पैकेजिंग।

**हम OpenCode को फ़ोर्क नहीं करते** जब तक कोई वर्टिकल स्लाइस साबित न करे कि
कोर सिमेंटिक्स (सिस्टम प्रॉम्प्ट, टूल व्यवहार, डिफ़ स्टेजिंग) बदलनी ही पड़ेंगी।
यह फ़ैसला सबूत पर होता है, मील के पत्थर 1 के बाद — पहले से नहीं।

छोड़ी खाली जगह बिल्कुल यही है: स्टैंडअलोन डेस्कटॉप, कोई अकाउंट नहीं, कोई
टेलीमेट्री नहीं, ब्राउज़र + worktree।

## शून्य टेलीमेट्री — सत्यापित

ऑडिट (मील का पत्थर 0) पूरा हुआ और व्यावहारिक रूप से सत्यापित। पूरे पुनरुत्पादन
चरण [docs/telemetry-audit.md](./docs/telemetry-audit.md) में।

- **शून्य थर्ड-पार्टी टेलीमेट्री।** कोर बाइनरी में Sentry, PostHog, Segment,
  Mixpanel, Datadog या कोई एनालिटिक्स SDK नहीं।
- **आउटबाउंड नेटवर्क कॉल ज़बरदास्ती बंद।** कन्वर्सेशन शेयरिंग
  (`"share": "disabled"`), सेल्फ़-अपडेट (`"autoupdate": false`) और Zen छोटे
  मॉडल फ़ोर्स्ड ऑन-डिस्क कॉन्फ़िग से बंद।
- **अलग-थलग वातावरण।** सारा स्टेट, कैश, db और लॉग ऐप डेटा डायरेक्टरी के भीतर
  (`XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`)।
- **सुरक्षा।** रैंडम 64-अक्षर पासवर्ड वाला HTTP Basic प्रमाणीकरण, केवल
  `127.0.0.1` पर बाइंड।

## वर्तमान स्थिति

BuzzAgent फिर से बनकर पूरी तरह कार्यशील है:
- **कोर सुपरवाइज़र (Rust)**: स्वचालित प्रोसेस प्रबंधन, रैंडम पोर्ट, पासवर्ड
  जनरेशन, हेल्थ चेक, वातावरण पृथक्करण, लूपबैक `NO_PROXY` बाईपास, बाहर निकलते
  समय साफ़ टियरडाउन।
- **डायरेक्ट HTTP + SSE क्लाइंट**: OpenCode कोर API से सीधा संपर्क, फ़्रेम-
  बाउंड्री लचीलापन वाला इवेंट स्ट्रीम पार्सिंग, सेशन प्रबंधन, मल्टी-टर्न
  मैसेजिंग, परमिशन गेटिंग।
- **विज़ुअल वर्कबेंच UI**: रीयल-टाइम स्ट्रीमिंग चैट, न झपकने वाला markdown,
  सिंटैक्स-हाइलाइटेड कोड ब्लॉक (Shiki), निरीक्षण-योग्य टूल कार्ड
  (स्थिति/अवधि/त्रुटि सहित), परमिशन डायलॉग।
- **विज़ुअल डिफ़ पैनल**: रीयल-टाइम git परिवर्तन व्यूअर, शब्द-स्तरीय मार्क
  (`+`/`−`), एक क्लिक फ़ाइल रिवर्ट।
- **इन-ऐप ब्राउज़र पैनल**: हेडलेस Chrome ऑटोमेशन और लाइव CDP अटैच
  (`http://127.0.0.1:9222`), लाइव व्यूपोर्ट स्क्रीनशॉट स्ट्रीम, सेलेक्टर
  इंटरैक्शन (क्लिक, टाइप), रीयल-टाइम CDP कंसोल लॉग व्यूअर।
- **Worktree ऑर्केस्ट्रेशन**: ब्रांच-अनुसार अलग git worktree बनाना व
  प्रबंधित करना, चालू प्रोजेक्ट तुरंत बदलना।
- **कमांड पैलेट (`⌘K`)**: कीबोर्ड-फ़र्स्ट तेज़ नेविगेशन — पैनल, सेशन, थीम
  (डार्क, लाइट, सिस्टम)।

## त्वरित शुरुआत

### 1. पूर्वापेक्षाएँ और सेटअप

```bash
npm install
npm run setup:core   # पिन किया OpenCode बाइनरी src-tauri/bin में डाउनलोड
```

### 2. डेस्कटॉप ऐप चलाएँ

```bash
npm run dev          # Tauri डेस्कटॉप ऐप + कोर की स्वचालित देखरेख
```

या Web प्रीव्यू:
```bash
npm run web          # केवल Vite — http://localhost:1420
```

### 3. इंस्टॉलर बनाएँ (Windows / macOS / Linux)

```bash
npm run dist         # पिन किया कोर डाउनलोड, फिर रिलीज़ इंस्टॉलर बिल्ड
```

आर्टिफ़ैक्ट `src-tauri/target/release/bundle/` में:

| OS | फ़ाइलें |
|---|---|
| Windows | `.msi`, NSIS `.exe` |
| macOS | `.app`, `.dmg` (आर्किटेक्चर-वार: `--target aarch64-apple-darwin` / `x86_64-apple-darwin`) |
| Linux | `.deb`, `.rpm`, `.AppImage` |

पिन किया OpenCode कोर **हर इंस्टॉलर के भीतर** जाता है (`bundle.externalBin`),
इसलिए अंतिम यूज़र एक फ़ाइल इंस्टॉल करता है और टर्मिनल कभी नहीं छूता।

रिलीज़ बंडलिंग के बिना तेज़ पुनरावृत्ति: `npm run dist:debug`।

### 4. यूज़र्स तक रिलीज़ (तीनों OS के लिए एक ही कमांड)

वर्शन टैग पुश होने पर सब OS के इंस्टॉलर CI से बनते हैं:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

GitHub Actions (`.github/workflows/release.yml`) Windows `.msi`/`.exe`,
macOS `.dmg` (Apple Silicon + Intel) और Linux `.deb`/`.rpm`/`.AppImage` बनाकर
GitHub Release से जोड़ देता है। डेस्कटॉप ऐप के लिए यही `npm install -g` के
सबसे क़रीब है: यूज़र Releases पेज पर एक लिंक पर क्लिक करता है।

> ध्यान दें: `npm install -g` CLI टूल्स के लिए है। BuzzAgent डेस्कटॉप GUI
> ऐप है, वितरण इंस्टॉलर से होता है; कोई ग्लोबल-इंस्टॉल पाथ नहीं।

### 5. सत्यापन और टेस्ट

```bash
npm run typecheck    # TypeScript सख़्त जाँच
npm run lint         # ESLint 9
npm test             # Vitest यूनिट सूट (markdown, diff, client, store, UI)
cd src-tauri && cargo test   # Rust सुपरवाइज़र, git, ब्राउज़र टेस्ट
npm run test:integration     # लाइव OpenCode + mock प्रोवाइडर पर एंड-टू-एंड
```
