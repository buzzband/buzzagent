**BuzzAgent** — open-source визуальная среда для AI-кодинг-агентов. Ядро
агента — [OpenCode](https://github.com/anomalyco/opencode) (MIT); BuzzAgent —
GUI-клиент вокруг него, а не ещё один агентный рантайм.

> **Видно всё, что делает агент. Управление моделями, тулами, браузером, MCP
> и reasoning-ом — локально, с нулевой телеметрией.**

## Почему это существует

Рынок расколот: визуальные инструменты слабые, сидят в VS Code и везут
телеметрию (Cline, Kilo Code, Roo Code); мощные агенты слепые и живут в
терминале (OpenCode, Claude Code, Codex CLI, Oh My Pi). Дыра — продукт,
который оставляет мощь терминального агента и даёт визуальный контроль,
без телеметрии и вендор-лока.

BuzzAgent не переписывает агента. OpenCode уже является headless HTTP-сервером
(`opencode serve`): OpenAPI-спека, SSE, типизированный JS SDK. Их TUI — один
клиент этого сервера, IDE-плагины — второй. BuzzAgent — третий: отдельное
десктоп-приложение.

Kilo Code CLI — **форк** OpenCode, обёрнутый в расширение VS Code с аккаунтами
и телеметрией. Мы это не копируем: форк отрезает от апстрима, а клиент получает
обновления ядра бесплатно.

### Как это устроено

Фронтенд говорит с ядром **напрямую** по HTTP и SSE (`@opencode-ai/sdk`,
спека с `GET /doc`, версия ядра прибита). Rust не проксирует агентный трафик.
Rust только поднимает и сторожит процесс `opencode serve` (случайный порт,
пароль, health-чек) и даёт нативные вещи, которых в ядре нет: встроенный
браузер (CDP) и git worktrees.

Состояние ядра одно. Пример: пользователь вставляет API-ключ → UI вызывает
`PUT /auth/:id` → ядро само пишет `auth.json`. Ключ не лежит в нашем сторе или
localStorage. Провайдеры и ключи можно возить в обе стороны: **импорт** из
личного стейта opencode CLI и **экспорт** обратно — merge-only, без перезаписи.

### Возможности

- **Чат со стримингом**: карточки тулов с состояниями и длительностью,
  reasoning по ролям, роутер моделей. Слэш-команды: `/init` (написать
  AGENTS.md), `/compact`, `/export`, `/copy`, `/undo`, `/redo`, `/help`;
  ссылки на файлы через `@`, shell-пасcthrough через `!команда`. Проектные
  команды (`GET /command`) всегда приоритетнее встроенных.
- **Визуальные диффы** с подсветкой на уровне слов и откатом одного файла;
  параллельные агенты по worktree на ветку.
- **Провайдеры**: 75+ через ядро; ключ или OAuth; в пикере моделей — раздел
  «доступно для подключения» с вводом ключа на месте; двусторонняя синхронизация
  с личным CLI-стейтом opencode.
- **Инсайт сессии**: суммарные токены/стоимость и индикатор заполнения
  контекстного окна в статус-баре, детализация по сообщениям.
- **Рабочий стол**: своя шапка окна (стиль VS Code) или системная рамка,
  иконка в трее, 15 языков интерфейса (включая русский).

### Почему Tauri

Горячий путь (стриминг, карточки, диффы) идёт из вебвью прямо в ядро по
HTTP/SSE и **не проходит** через Tauri IPC. Нативный слой всё равно нужен и
уже написан; Electron — стек их десктопа, где у авторов ядра форы (оставлен
как задокументированный fallback). Честная цена: три разных вебвью, слабейший —
`webkit2gtk` на Linux.

### Телеметрия — проверено

Аудит завершён и подтверждён на практике ([docs/telemetry-audit.md](../docs/telemetry-audit.md)):
- Ноль сторонних аналитических SDK в бинарнике ядра.
- Исходящие каналы отключены принудительным конфигом (`share: "disabled"`,
  `autoupdate: false`), все четыре XDG-корня изолированы внутри папки приложения.
- HTTP Basic со случайным 64-символьным паролем, биндинг только на `127.0.0.1`.

### Быстрый старт

```bash
npm install
npm run setup:core   # скачать прибитый бинарник ядра OpenCode
npm run dev          # десктоп-приложение
npm run dist         # сборка установщиков (ядро внутри)
```

Сборки для Windows/macOS/Linux делает CI по тегу (`git tag v0.1.0 && git push
origin v0.1.0`) и прикладывает к GitHub Release.

### Проверки

```bash
npm run typecheck && npm run lint && npm test
cd src-tauri && cargo test
```
