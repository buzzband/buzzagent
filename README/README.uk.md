# BuzzAgent — Українська (README.uk.md)

🌐 Сайт проєкту: **https://b4zz.com/agent**

⬇️ **Завантажити:** [https://b4zz.com/agent/#download](https://b4zz.com/agent/#download)

Open-source візуальне робоче середовище для AI-кодинг-агентів. Ядро агента —
[OpenCode](https://github.com/anomalyco/opencode) (MIT); BuzzAgent — GUI-клієнт
навколо нього, а не ще один агентний рантайм.

> **Видно все, що робить агент. Керування моделями, інструментами, браузером,
> MCP та reasoning-ом — локально, з нульовою телеметрією.**

## Чому це існує

Ринок розколотий навпіл:

**Візуальні, але слабкі.** Cline, Kilo Code, Roo Code — UI придатний, але
замурований у VS Code, з телеметрією та слабшим агентним циклом.

**Могутні, але сліпі.** OpenCode, Claude Code, Codex CLI, Oh My Pi — сильний
агент, але термінал. Немає візуальних дифів, немає вбудованого браузера, немає
оркестрації робочих просторів.

Проріха — це продукт, який зберігає міць термінального агента **і** дає
візуальний контроль, без телеметрії та вендор-лока.

BuzzAgent — цей продукт. Він **не перевинаходить агента**. OpenCode вже є
headless HTTP-сервером (`opencode serve`) зі спекою OpenAPI, SSE-потоком
подій і типізованим JS SDK. Їхній TUI — один клієнт цього сервера; їхні
IDE-плагіни — другий. BuzzAgent — третій: самостійний десктопний застосунок.

CLI Kilo Code — це **форк** OpenCode, обгорнутий у розширення VS Code (лінія
Cline) з акаунтами та телеметрією. Ми це не копіюємо. Форк успадковує їхню
вартість підтримки й відрізає від апстріму. Клієнт отримує свіже ядро, доки
OpenCode постійно випускає релізи.

### У OpenCode тепер є власний GUI

З версії 1.18 репозиторій OpenCode публікує збірки `opencode-desktop-*`
(Electron + SolidJS, ~120–150 МБ) та браузерний режим (`opencode web`).
«Візуальний клієнт для OpenCode» сам по собі **більше не диференціатор** — у
авторів ядра він свій.

Що залишається нашим:

- **Нуль телеметрії як перевірений факт.** Їхній десктоп інтегрує
  `@sentry/solid` та ініціалізує його, якщо під час збірки задано
  `VITE_SENTRY_DSN` (`packages/desktop/src/renderer/index.tsx`), плюс
  `sentryVitePlugin` у збірці. У нашому процесі немає ані crash-репортера,
  ані жодної аналітичної залежності.
- **Браузер усередині циклу агента** — пише код, відкриває результат,
  скриншот повертається як результат інструмента, агент виправляє. Не лише
  headless: можна під'єднатися й до запущеного Chrome через CDP, щоб агент
  працював у профілі, де користувач уже залогінений (за дозволами, як
  `shell_exec`).
- **Оркестрація worktree** — кілька агентів паралельно на ізольованих гілках,
  з візуальним монітором.
- **Без акаунта, без вбудованого гейтвея.** Немає шляху за замовчуванням через
  Zen/Go.

Наслідок: наш GUI порівнюватимуть з їхнім напряму. Це піднімає планку, і тому
Milestone 1 — вузький надійний зріз, а не широка махина фіч.

Корисний прецедент з їхнього десктопу: `packages/desktop/src/main/sidecar.ts`
запускає сервер із `OPENCODE_SERVER_PASSWORD`, випадковим портом, CORS,
обмеженим власним origin, із примусовим додаванням loopback у `NO_PROXY` та
завантаженням системних CA-сертифікатів. Ми застосовуємо те саме загартування.

## Архітектура

```
┌─────────────────────────────────────────────────────────┐
│  BuzzAgent (Tauri + React)                              │
│                                                         │
│  Візуальний шар ──HTTP + SSE──►  opencode serve          │
│  чат · дифи · файли ·            (бінарник sidecar,       │
│  провайдери · дозволи ·           прибита версія)         │
│  worktrees                                               │
│                                                         │
│  Шар Rust                                                │
│  · наглядає за процесом ядра                              │
│  · вбудований браузер (CDP) ──зареєстрований як тул──     │
│  · оркестрація git worktrees                              │
└─────────────────────────────────────────────────────────┘
```

- **Ядро = OpenCode.** Цикл інструментів, нативний function calling,
  стримінг, сесії та відновлення, компакція, дозволи, LSP, MCP,
  grep/glob/symbols, AGENTS.md, скіли, слеш-команди, 75+ провайдерів, OAuth.
  Ми нічого з цього не переписуємо.
- **GUI = BuzzAgent.** Чат із картками викликів інструментів, візуальні дифи,
  дерево файлів, вхідні дозволи, керування моделлю/зусиллям за ролями,
  монітор worktree.
- **Нативні доповнення, яких немає в ядрі.** Вбудований браузер у циклі
  агента; паралельні агенти в ізольованих git worktree.

Фронтенд спілкується з ядром **напряму** через HTTP і SSE, через
`@opencode-ai/sdk`, згенерований зі спеки OpenAPI **прибитої** версії
(`GET /doc`). Rust не проксіює агентний трафік. Rust лише:

1. Запускає та наглядає `opencode serve` (випадковий порт, пароль,
   health-чек).
2. Відкриває нативні інструменти, які ядро саме не вміє (браузер, worktree).

Це той самий поділ, що OpenCode використовує всередині: TUI — клієнт,
сервер — рантайм.

## Чому Tauri (і чого це коштує)

Гарячий шлях — стримінгові токени, картки інструментів, дифи — іде з вебвью
прямо в локальне ядро через HTTP/SSE. Він **не проходить** через Tauri IPC,
тому пропускна здатність IPC шелла не на критичному шляху. Десктопний шелл —
рішення про пакування та нативні можливості, а не про продуктивність.

Tauri, тому що:

- Нативний шар нам усе одно потрібен — для нагляду за процесами, керування
  браузером через CDP та git worktree; цей код написаний і його тести
  проходять.
- Перехід на Electron ставить нас рівно на стек їхнього десктопу (Electron +
  SolidJS + sidecar), де автори ядра мають фору, а нам немає чим відрізнитися.
- Їхній шаблон Electron несе інтеграцію з Sentry. Обіцянку «нуль телеметрії»
  простіше тримати правдою на стеку, який контролюємо ми.
- Розмір бандла тут слабкий аргумент: один бінарник ядра ~57 МБ, тож 5 МБ
  проти 120 МБ шелла нічого не вирішує.

Реальна ціна, без прикрас:

- **Три різні вебвью.** WebView2 (Chromium, самоновний) на Windows,
  WKWebView на macOS, `webkit2gtk` на Linux. За таблицею самого Tauri,
  `webkit2gtk` 2.36 ≈ Safari 16, а старіші дистрибутиви ще далі. Linux —
  найслабша ціль, і баги рендерингу проявляться там першими. Пом'якшення:
  консервативний CSS, без передових веб-API, тести на справжньому
  `webkit2gtk`.
- **Кілька вебвью в одному вікні заховані за прапорцем `unstable` Tauri.** Це
  важливо для панелі браузера: надаємо перевагу CDP + скриншотам/стриму в UI,
  а не другому живому вебвью, або окремому вікну.
- Час збірки Rust і менша екосистема плагінів, ніж у Electron.

### Розглянуті альтернативи

| Варіант | Вердикт |
|---|---|
| **Electron** | Найпередбачуваніша UX: один Chromium усюди, найкраща екосистема, прості devtools. Відхилений як дефолт, бо це рівно стек десктопу OpenCode, а нативний код усе одно писався б node-аддонами. Чесний запасний варіант, якщо баги `webkit2gtk` стануть некерованими. |
| **Go + Wails** | Та сама модель системного вебвью, що в Tauri, — та сама проблема `webkit2gtk` — плюс відмова від уже написаного Rust-коду. Go тут нічого не купує: ядро не на Go, і наша нативна робота (CDP, worktree, нагляд) на Go не простіша. |
| **Чистий Rust GUI** (egui, Iced, GPUI, Dioxus native, Slint) | Усуває весь клас багів вебвью й дає справжню нативну продуктивність. Але чат, markdown, підсвітку синтаксису, дифи та дерево файлів довелося б писати руками — рівно та поверхня, за якою судять GUI кодинг-агента. Гак на роки, а панель браузера стає майже нездійсненною. Для v1 нежиттєздатно. |
| **Лише веб-UI** (свій фронтенд у браузері) | Найдешевше, і справді корисний вторинний варіант — але OpenCode вже дає `opencode web`, а вкладка браузера не може володіти нативними меню, worktree чи вбудованим браузером. Добре як додатковий режим згодом, не як продукт. |
| **Flutter / .NET / Qt** | Нативні віджети, але без повторного використання React, а екосистема «markdown + дифи + код» слабша за веб. Велике переписування без стратегічного виграшу. |
| **Розширення VS Code** | Знайоме й дешеве, але це коробка Cline/Kilo, проти якої ми позиціонуємось явно, і воно вбиває історію автономного застосунку без телеметрії. |

Рішення: **зараз Tauri + React**, Electron — задокументований запасний варіант,
якщо дефекти вебвью на Linux стануть некерованими. Тримати UI простим
HTTP/SSE-клієнтом ядра — саме це робить запасний варіант дешевим: шелл
замінний, бо агентна логіка в ньому не живе.

### Чому не Oh My Pi як ядро

[oh-my-pi](https://github.com/can1357/oh-my-pi) (MIT, ~30k зірок) — сильний
агент, місцями глибший за OpenCode: LSP у циклі, DAP, hashline-правки, велика
нативна Rust-прошарка, URI-схеми `pr://`/`issue://`/`agent://`, ланцюги
фолбеку моделей. Але *для цього продукту* це все одно не те ядро:

- **Немає HTTP-сервера.** Його чотири поверхні — TUI, one-shot промпт,
  in-process Node SDK і `--mode rpc` / `acp` через **stdio**. Браузер не
  говорить на stdio, тож Rust мусив би проксіювати кожне повідомлення — та
  прошарка, яку ми навмисно прибрали, — а їхній RPC вимагає ручного нарізання
  кадрів по 1 МіБ і узгодження протоколу. Немає OpenAPI-спеки — немає
  згенерованого клієнта.
- **Телеметрія, яку не вимкнути.** Постійний install-UUID
  (`~/.omp/install-id`, описаний в їхньому `docs/install-id.md`) переживає
  очистку стану агента і годує, серед іншого, звіт про використання
  auth-брокеру, куди йде ще й hostname, плюс авто-QA пуші. Прибрати це —
  форкнути їхній рантайм, що перекреслює сенс чужого ядра.
- **Ніша зайнята:** `gooey-pi`, `pi-desktop`, `ohmypi-craft`, `ompweb` — уже
  GUI для OMP.

Якщо колись додамо друге ядро — то через **ACP**, спільний протокол, за
адаптерним інтерфейсом, і тільки коли зріз OpenCode стане міцним.

## Якість інтерфейсу — це продукт

Усе вище — сантехніка. Причина обрати BuzzAgent — інтерфейс, тому до нього
вимоги стандарту, а не «працює ж»: нічого не блокується по мережі, 60 fps під
час стримінгу, без стрибків верстки, клавіатура попереду, справжні
side-by-side дифи з підсвіткою синтаксису, довгі сесії з віртуалізацією,
продумані порожні/помилкові/офлайн-стани, темна **й** світла теми, і справжня
доступність (фокус, контраст, підтримка скрінрідера для потоку повідомлень).

Повна планка, обраний фронтенд-стек (React 19, Tailwind 4, Radix, Shiki,
CodeMirror 6, TanStack Virtual, cmdk) і правила додавання залежностей — у
PLAN.md.

## Як налаштування дістається до ядра

UI ніколи не тримає другу копію стану ядра. Приклад — користувач вставляє
API-ключ:

1. Панель моделей викликає `GET /provider/auth`. Форма рендериться зі схеми,
   яку повернуло ядро (API-ключ, OAuth, device flow, …).
2. Під час збереження UI викликає `PUT /auth/:id`. Ядро саме пише
   `~/.local/share/opencode/auth.json`. Ключ не лежить у нашому сторі й не в
   `localStorage`.
3. Base URL, білий список моделей, `share: "disabled"` ідуть через
   `PATCH /config`.
4. Пікер моделей — `GET /config/providers` / `GET /provider`.
5. Модель ходу — поле в `POST /session/:id/message` (`model`, `agent`).
   «Роутер за ролями» — це наш UI, що вибирає ці поля, а не другий HTTP-клієнт
   перед 75 провайдерами.

OAuth-провайдери (Claude Pro, Copilot, GitLab Duo, DigitalOcean) використовують
`POST /provider/{id}/oauth/authorize` → системний браузер →
`POST /provider/{id}/oauth/callback. Жодного специфічного для провайдерів коду
на нашому боці.

Якщо два стори знову розійдуться — агент не стартує. Ядро — єдиний власник
конфігурації, сесій, дифів і дозволів.

## Що ми робимо і чого не робимо

**Ми не пишемо:** провайдерів, OAuth, цикл інструментів, стримінг, сесії,
компакцію, рушій дозволів, LSP, MCP, grep/glob/symbols, AGENTS.md,
слеш-команди, скіли, тудушки.

**Ми пишемо:** весь візуальний шар; вбудований браузер як тул ядра; оркестрацію
worktree; вхідні дозволи; візуальний роутер моделі/зусилля; нагляд за
процесами; пакування.

**Ми не форкаємо OpenCode**, доки якийсь вертикальний зріз не доведе, що треба
міняти семантику ядра (системні промпти, поведінку інструментів, стейджинг
дифів). Рішення приймається за доказами, після Milestone 1, а не завчасно.

## Позиціювання

```
BuzzAgent = ядро OpenCode
          + візуальний контроль рівня Cline
          + оркестрація worktree рівня Orca
          + вбудований браузер у циклі агента
          + нуль телеметрії
```

| | BuzzAgent | Cline / Kilo | Cursor | Claude Code | OpenCode |
|---|---|---|---|---|---|
| Open source | так | так | ні | ні | так |
| Нуль телеметрії | так (аудитовано — див. нижче) | ні | ні | ні | майже (share/Zen опційно) |
| Візуальний GUI | автономний десктоп | VS Code | так | ні | TUI / web |
| Вбудований браузер у циклі | так | ні | ні | ні | ні |
| Оркестрація worktree | так | ні | ні | ні | лише сесії |
| Субагенти, LSP, MCP, дозволи | через ядро | частково | частково | так | так |
| Агностик до ядра згодом | адаптерний інтерфейс, OpenCode першим | ні | ні | ні | n/a |

Kilo Code довів, що ядро OpenCode витримує продукт, і MIT це дозволяє. Далі
вони зайняли нішу IDE + телеметрія + білінг. Ніша, яку вони лишили відкритою, —
рівно ця: автономний десктоп, без акаунта, без телеметрії, браузер + worktree.

## Нуль телеметрії — перевірено

Аудит (Milestone 0) завершено й підтверджено емпірично. Повні кроки
відтворення — у [docs/telemetry-audit.md](./docs/telemetry-audit.md).

- **Нуль сторонньої телеметрії.** У бінарнику ядра немає Sentry, PostHog,
  Segment, Mixpanel, Datadog і жодних аналітичних SDK.
- **Вихідні мережеві виклики примусово вимкнено.** Шеринг розмов
  (`"share": "disabled"`), самооновлення (`"autoupdate": false`) та дрібні
  моделі Zen вимкнені форсованим конфігом на диску.
- **Ізольоване середовище.** Увесь стан, кеш, база й логи ізольовані всередині
  папки даних застосунку (`XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME`,
  `XDG_CACHE_HOME`).
- **Безпека.** HTTP Basic із випадковим 64-символьним паролем, прив'язка лише
  до `127.0.0.1`.

## Поточний стан

BuzzAgent перезібрано й повністю працездатний:
- **Супервізор ядра (Rust)**: автоматичне керування процесом, виділення
  випадкового порту, генерація пароля, health-чеки, ізоляція середовища, обхід
  `NO_PROXY` для loopback, чисте завершення при виході.
- **Прямий HTTP + SSE клієнт**: пряме підключення до API ядра OpenCode, розбір
  потоку подій зі стійкістю до меж кадрів, керування сесіями, багатоходові
  повідомлення, гейтинг дозволів.
- **Візуальний робочий стіл UI**: чат зі стримінгом у реальному часі без
  мерехтливого markdown, блоки коду з підсвіткою (Shiki), інспектовані картки
  інструментів зі станами/тривалостями/помилками, діалоги дозволів.
- **Панель візуальних дифів**: перегляд git-змін у реальному часі з
  послівними позначками (`+`/`−`) та відкатом файлу в один клік.
- **Панель вбудованого браузера**: автоматизація headless Chrome і живе CDP
  підключення (`http://127.0.0.1:9222`), стрим скриншотів в'юпорта,
  взаємодія через селектори (клік, введення), перегляд консолі CDP в
  реальному часі.
- **Оркестрація worktree**: створення й керування ізольованими git worktree за
  гілками, миттєве переключення активного проєкту.
- **Палітра команд (`⌘K`)**: швидка клавіатурна навігація по панелях, сесіях
  і темах (Темна, Світла, Системна).

## Швидкий старт

### 1. Передумови й налаштування

```bash
npm install
npm run setup:core   # завантажити прибитий бінарник OpenCode у src-tauri/bin
```

### 2. Запуск десктопного застосунку

```bash
npm run dev          # Tauri-застосунок + автоматичний нагляд за ядром
```

Або веб-прев'ю:
```bash
npm run web          # лише Vite — http://localhost:1420
```

### 3. Збірка установників (Windows / macOS / Linux)

```bash
npm run dist         # завантажити прибите ядро, потім зібрати установники релізу
```

Артефакти лягають у `src-tauri/target/release/bundle/`:

| ОС | Файли |
|---|---|
| Windows | `.msi`, NSIS `.exe` |
| macOS | `.app`, `.dmg` (за архітектурою: `--target aarch64-apple-darwin` / `x86_64-apple-darwin`) |
| Linux | `.deb`, `.rpm`, `.AppImage` |

Прибите ядро OpenCode кладеться **всередину** кожного установника
(`bundle.externalBin`): кінцевий користувач ставить один файл і ніколи не
торкається терміналу.

Швидка ітерація без пакування релізу: `npm run dist:debug`.

### 4. Реліз користувачам (одна команда на всі три ОС)

Установники для всіх ОС збирає CI при пуші тега версії:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

GitHub Actions (`.github/workflows/release.yml`) збирає `.msi`/`.exe` для
Windows, `.dmg` для macOS (Apple Silicon + Intel) і `.deb`/`.rpm`/`.AppImage`
для Linux та прикріплює їх усі до GitHub Release. Це найближчий еквівалент
`npm install -g` для десктопного застосунку: користувач клікає одне посилання
на сторінці Releases.

> Примітка: `npm install -g` — для CLI-інструментів. BuzzAgent — десктопний
> GUI-застосунок; дистрибуція через установники; глобальної установки немає.

### 5. Верифікація і тести

```bash
npm run typecheck    # строга перевірка TypeScript
npm run lint         # ESLint 9
npm test             # юніт-набір Vitest (markdown, diff, client, store, UI)
cd src-tauri && cargo test   # тести Rust: супервізор, git, браузер
npm run test:integration     # наскрізний тест проти живого OpenCode + mock-провайдера
```
